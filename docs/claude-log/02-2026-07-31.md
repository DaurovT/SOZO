## Почему карта не работала

Свободная карта там **уже стоит** — Leaflet + OpenStreetMap ([Map.tsx:74](sozo/apps/admin-web/src/pages/Map.tsx#L74)), ключей и оплаты не требует. Ломалась не карта, а порядок рендера:

```tsx
useEffect(() => {
  if (containerRef.current === null || mapRef.current !== null) return;  // ← выходил навсегда
  const map = L.map(containerRef.current)...
}, []);                                                                   // ← и больше не запускался

if (loading && data === null) return <Loading />;                         // ← первый рендер: div'а нет
```

На первом рендере `useFetch` отдаёт `loading: true`, компонент возвращает `<Loading />`, и `<div className="map-canvas">` в DOM отсутствует. Эффект с пустым списком зависимостей срабатывает ровно один раз — именно в этот момент, видит `containerRef.current === null` и выходит. Когда данные приходят и контейнер наконец появляется, повторно эффект уже не вызывается. Поэтому в области карты чистый белый прямоугольник — нет ни тайлов, ни кнопок зума, ни подписи «© OpenStreetMap». Leaflet просто не создавался.

## Что изменил

В [Map.tsx](sozo/apps/admin-web/src/pages/Map.tsx):

1. Инициализация переведена с `useEffect([])` на **callback-ref** — карта создаётся в тот момент, когда контейнер реально попал в DOM, независимо от того, на каком рендере это произошло. Отсоединение узла корректно вызывает `map.remove()`.
2. Флаг `mapReady` добавлен в зависимости эффектов наполнения слоёв и переключения видимости — иначе данные, пришедшие раньше карты, не отрисовались бы.
3. Ранние `return <Loading />` / `<ErrorBanner />` убраны: теперь они рендерятся **над** картой, контейнер из DOM не пропадает.
4. Тайлам проставлен `maxZoom: 19` — предел OSM; без него на глубоком зуме были бы серые квадраты.

## Важный нюанс: где приоритет работает, а где нет

Это, наверное, главное, что стоит помнить.

**Работает** — при освобождении слота. `release()` сортирует лист ожидания по приоритету и отдаёт слот старшему ([scheduling.service.ts:295](sozo/apps/api/src/modules/scheduling/scheduling.service.ts#L295)).

**Не работает** — при захвате занятого слота. `book()` на пересечении просто отдаёт `SLOT_BUSY` и не смотрит, кто там стоит ([scheduling.service.ts:249-252](sozo/apps/api/src/modules/scheduling/scheduling.service.ts#L249-L252)). B2B не вытесняет уже подтверждённую B2C-бронь автоматически — это соответствует ТЗ («подтверждённые брони не ломают»).
