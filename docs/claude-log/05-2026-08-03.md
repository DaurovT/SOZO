### Claude · 08:36

Отдельной регистрации в клиентском приложении нет — **регистрация = первый вход по номеру телефона**. Учётная запись и профиль заводятся сервером сами, «по факту» первого успешного OTP.

## Экран: один `LoginFlow` с четырьмя состояниями

[login_screen.dart:26](sozo/apps/client-app/lib/screens/login_screen.dart#L26) — не четыре маршрута, а enum `splash → phone → code → consents` внутри одного виджета, чтобы между шагами не терялись номер и таймер повтора.

| Шаг | Что происходит |
|---|---|
| **C-01** splash | Выбор языка ru/uz, кнопка «Начать». Долгое нажатие по версии открывает смену адреса сервера ([:254](sozo/apps/client-app/lib/screens/login_screen.dart#L254)) — для запуска на реальном телефоне |
| **C-02** телефон | Маска `90 123-45-67`, префикс `+998` отдельным виджетом; валидно ровно 9 цифр → `POST /auth/request-otp` |
| **C-03** код | 5 ячеек поверх невидимого `TextField` (чтобы работал автоввод SMS), последняя цифра сама шлёт `POST /auth/verify`; 3 попытки, таймер повтора 59 с |
| **C-04** согласия | Обязательное — на обработку персданных, опциональное — маркетинг → `POST /app/consents` |

## Ключевое решение: токен есть, но сессии ещё нет

[login_screen.dart:106-116](sozo/apps/client-app/lib/screens/login_screen.dart#L106-L116) — после `verify` токен кладётся в `_pendingToken`, а не в сессию. Сразу дёргается `/app/me`, и если `consents.personalData == true` — вход завершается, иначе показывается шаг согласий. Причина указана в комментарии: у `/auth/verify` нет признака «новый клиент», отличить его можно только по профилю. Сессия фиксируется через `session.signIn()` ([session.dart:83](sozo/apps/client-app/lib/store/session.dart#L83)) только после согласия — то есть отвалившийся на C-04 пользователь не считается вошедшим.

## Что делает сервер

1. **`/auth/request-otp`** ([identity.controller.ts:11](sozo/apps/api/src/modules/identity/identity.controller.ts#L11)) — проверяет формат `+998\d{9}` и просто пишет код в лог. Боевого SMS-шлюза нет, код всегда `00000` ([identity.service.ts:6](sozo/apps/api/src/modules/identity/identity.service.ts#L6)).
2. **`/auth/verify`** ([identity.service.ts:123](sozo/apps/api/src/modules/identity/identity.service.ts#L123)) — неизвестный телефон молча создаётся с ролью `client` и именем `Клиент XXXX` ([:138](sozo/apps/api/src/modules/identity/identity.service.ts#L138)). Роль `master` подтягивается на каждом входе через role-providers. Выдаётся JWT на 12 часов; вход (и удачный, и неудачный) пишется в журнал.
3. **Профиль клиента** живёт отдельно от учётки — [client-profiles.service.ts:92](sozo/apps/api/src/modules/client-b2c/client-profiles.service.ts#L92): «Профиль создаётся при первом обращении: отдельной регистрации у клиента нет». В `identity` — кто вошёл и его роли, в `client-b2c` — что человек сам про себя сообщил.
4. **`/app/consents`** ([client-b2c.controller.ts:250](sozo/apps/api/src/modules/client-b2c/client-b2c.controller.ts#L250)) — ставит флаги, язык, пишет в аудит. Отзыв согласия через приложение запрещён (`CONSENT_WITHDRAWAL_VIA_SUPPORT`) — только через поддержку, ТЗ 14.

## После входа

`ContextGate` ([context_screen.dart](sozo/apps/client-app/lib/screens/context_screen.dart)) тянет `/app/me` и решает: если телефон вписан ответственным в карточки точек B2B — показывает выбор контекста (C-05), иначе сразу `AppShell`. Токен, телефон, base URL и выбранный контекст хранятся в `SharedPreferences`.

## На что стоит обратить внимание

- **ФИО не спрашивается нигде** — ни при регистрации, ни в профиле. `fullName` в `/app/me` подставляется из `clientName` первой заявки ([client-b2c.controller.ts:187](sozo/apps/api/src/modules/client-b2c/client-b2c.controller.ts#L187)), иначе пусто и в UI показывается номер. `setConsents` умеет принимать `fullName`, но приложение его не шлёт.
- **Лимит попыток и таймер повтора — только на клиенте.** Сервер не хранит ни выданный код, ни счётчик попыток, ни срок жизни: `verify` сравнивает со статической константой. Пока это заглушка — не проблема, но при подключении SMS-шлюза сюда нужны стейт кода, TTL, одноразовость и rate-limit по номеру/IP.
- **Мёртвая ветка:** на шаге телефона обрабатывается ошибка `ACCOUNT_BLOCKED` ([login_screen.dart:83](sozo/apps/client-app/lib/screens/login_screen.dart#L83)), но `request-otp` её никогда не возвращает — блокировка проверяется в `verify` и приходит кодом `USER_BLOCKED`. Диалог «доступ закрыт» не покажется, вместо него будет обычный текст ошибки на экране кода.
