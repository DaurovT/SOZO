# DEV-06. Временный UI-гайд USTAPRO / SOZO

**Статус:** временный. Финальный дизайн владелец сделает сам позже. Задача команды — единый простой стиль «в духе Claude» (тёплый минимализм Anthropic: кремовые фоны, терракотовый акцент, мягкие скругления, спокойная типографика, много воздуха), чтобы всё работало и выглядело опрятно без дизайнера.

**Область действия:** Flutter-приложения «Клиент» и «Мастер», web-панели «Диспетчерская» и «Админка», лендинги.

---

## 1. Принципы

1. **Контент важнее хрома.** Никаких декоративных рамок, подложек и украшений — экран состоит из данных и действий.
2. **Один акцентный цвет.** Янтарь из фирменного знака используется только для главного действия экрана, активных состояний и денег мастера; всё остальное — нейтральное. Палитра выведена из логотипа: янтарь #FEB70F на почти-чёрном #141518.
3. **Тени не сильнее 8% чёрного.** `rgba(0,0,0,0.08)`, blur ≤ 16, смещение по Y ≤ 4. Глубина в основном за счёт границ и фона, не теней.
4. **Никакой кастомной графики.** Только системные иконки Material Symbols (outlined). Ни иллюстраций, ни собственных пиктограмм, ни клипарта.
5. **Плотность по контексту.** Мобайл (Клиент, Мастер) — просторно: крупные тапы, отступы 16–24. Диспетчерская и Админка — компактные таблицы: высота строки 36–40, отступы 8–12.

---

## 2. Токены

Единственный источник правды для всех значений. В коде — только имена токенов, никогда «сырые» hex (см. раздел 6).

### 2.1. Цвета

| Токен | Значение | Назначение |
|---|---|---|
| `bg` | `#F6F6F8` | Фон экранов и страниц (холодный светло-серый — белые карточки читаются как слои) |
| `surface` | `#FFFFFF` | Карточки, модалки, поля ввода, строки таблиц |
| `text` | `#141518` | Основной текст (цвет фирменного знака) |
| `textSecondary` | `#8A8A93` | Вторичный текст: подписи, метаданные, плейсхолдеры |
| `textTertiary` | `#B4B4BD` | Третий уровень: единицы измерения, счётчики, служебные подписи |
| `accent` | `#FEB70F` | Акцент (янтарь из знака): primary-кнопки, активные табы, деньги мастера |
| `accentPressed` | `#E0A00A` | Pressed-состояние акцента |
| `onAccent` | `#141518` | Текст и иконки на янтарном фоне — белое по нему не читается на солнце |
| `success` | `#2FA36B` | Успех: «Закрыта», оплата прошла, синк ок |
| `warning` | `#F08C1E` | Предупреждение: паузы, «ожидает», просрочка SLA близко |
| `error` | `#E0483D` | Ошибка: аварийная, спор, отклонено, валидация |
| `info` | `#3D6BF5` | «Принято»: состояние подтверждено кем-то снаружи |
| `fresh` | `#7A5AF8` | «Новое»: требует внимания, но не тревожное |
| `border` | `#ECECF0` | Границы карточек, полей, зебра таблиц |
| `divider` | `#F2F2F5` | Разделитель внутри карточки — светлее внешней границы |

Для фонов бейджей и «мягких» подсветок использовать те же токены с прозрачностью 10–15% (например `accent` @ 12%), отдельных пастельных hex не заводить.

### 2.2. Радиусы

| Токен | Значение | Где |
|---|---|---|
| `radiusCard` | 12 | Карточки, модалки, bottom-sheet, фото-плитки |
| `radiusButton` | 8 | Кнопки, поля ввода, дропдауны |
| `radiusChip` | 999 | Чипы, статус-бейджи, аватары |

### 2.3. Отступы (шкала)

| Токен | Значение | Типовое применение |
|---|---|---|
| `s4` | 4 | Иконка↔текст внутри бейджа |
| `s8` | 8 | Между элементами внутри строки; паддинги ячеек таблиц |
| `s12` | 12 | Внутренний паддинг компактных карточек, чипов |
| `s16` | 16 | Паддинг карточек и экранов (мобайл), между полями формы |
| `s24` | 24 | Между секциями экрана |
| `s32` | 32 | Крупные секции лендинга, паддинг модалок на десктопе |

Промежуточные значения (10, 14, 20…) не использовать — только шкала.

## 3. Типографика

- **Шрифты — только системные**, кастомные не подключаем: iOS — SF Pro, Android — Roboto, web — `Inter, -apple-system, "Segoe UI", Roboto, sans-serif` (Inter подключается с Google Fonts только на лендингах; в панелях допустим чистый системный стек).
- Кириллица и узбекская латиница (ў, ғ, қ, ҳ, oʻ, gʻ) полностью покрываются системными шрифтами — **никаких спецшрифтов и подмен глифов не требуется**.

| Стиль | Размер | Насыщенность | Применение |
|---|---|---|---|
| `h1` | 24 | Semibold (600) | Заголовок экрана/страницы |
| `h2` | 20 | Semibold (600) | Заголовок секции, заголовок модалки |
| `body` | 16 | Regular (400) | Основной текст, поля, кнопки |
| `caption` | 13 | Regular (400) | Метаданные, подписи, текст бейджей — цвет `textSecondary` |

- Межстрочный интервал везде **1.4**.
- Жирность для выделения — 600, курсив не используем. В таблицах панелей допустим body 14 ради плотности — задаётся одним токеном `bodyDense`, не инлайн.

## 4. Компоненты

По одному абзацу на компонент: как выглядит + примечание по реализации.

### 4.1. Кнопки

**Primary** — заливка `accent`, текст белый, радиус `radiusButton`, высота 48 (мобайл) / 36 (панели), паддинг горизонтальный `s16`; hover/pressed — `accentHover`; disabled — `border` с текстом `textSecondary`. **Secondary** — прозрачный фон, обводка 1px `border`, текст `text`; hover — фон `accent` @ 8%. **Destructive** — как secondary, но текст и обводка `error`; заливку `error` использовать только в диалоге подтверждения. На экране — не больше одной primary-кнопки.
*Flutter:* `FilledButton` / `OutlinedButton` через `ThemeData` (`filledButtonTheme`, `outlinedButtonTheme`), никаких стилей на месте вызова. *Web:* классы `.btn`, `.btn--secondary`, `.btn--danger` на CSS-переменных.

### 4.2. Карточка заявки

Белая поверхность `surface` на кремовом фоне, радиус `radiusCard`, граница 1px `border`, без тени (или тень ≤ 8%), паддинг `s16`. Внутри сверху вниз: строка «№ заявки + статус-бейдж справа», категория и адрес (`body`), метаданные — время, сумма сметы, мастер (`caption`, `textSecondary`). Аварийная заявка — вертикальная полоса 3px цвета `error` по левому краю карточки, больше ничего не краснеет. Вся карточка кликабельна.
*Flutter:* общий виджет `OrderCard` в shared-пакете — Клиент/Мастер/(webview) используют один. *Web:* `.card` + `.card--emergency`.

### 4.3. Статус-бейджи

Чип радиусом `radiusChip`, текст `caption`, паддинг `s8`/`s4`, фон — цвет статуса @ 12%, текст — сам цвет (для серых — `textSecondary`). Маппинг статусов заявки (ТЗ 4.1) на цветовые группы:

| Группа | Статусы | Цвет |
|---|---|---|
| До назначения — нейтральные | Новая, Оценена, На утверждении, Утверждена | серый: фон `border`, текст `textSecondary` |
| В работе — активные | Мастер выехал, В работе, Доп-согласование | `accent` (янтарь) |
| Паузы (суб-состояния «В работе»: ожидание материалов, техперерыв, блок третьей стороной) | бейдж статуса остаётся терракотовым + второй бейдж паузы | `warning` |
| Закрыта | Закрыта | `success` |
| Критические | Аварийная (флаг), Спор | `error` |
| Терминальная негативная | Отменена | серый, текст перечёркнут |

Маппинг живёт в одной функции/константе `statusColor(status)` — используется всеми пятью продуктами, дублировать в компонентах запрещено.

### 4.4. Поля форм

Фон `surface`, граница 1px `border`, радиус `radiusButton`, высота 48 (мобайл) / 36 (панели), лейбл сверху (`caption`, `textSecondary`), плейсхолдер `textSecondary`. Фокус — граница `accent` 1.5px, без свечения. Ошибка — граница `error` + текст ошибки `caption` цветом `error` под полем; поле никогда не «прыгает» — место под ошибку резервируется или используется компактный отступ.
*Flutter:* один `InputDecorationTheme` в `ThemeData`. *Web:* `.input`, состояния через `:focus` и `.input--error`.

### 4.5. Таббар / навигация

Мобайл — нижний таббар: фон `surface`, верхняя граница 1px `border`, иконки Material Symbols; активная вкладка — иконка и подпись `accent`, неактивные — `textSecondary`; без индикаторов-«пилюль». Панели (Диспетчерская, Админка) — левый сайдбар шириной ~240: фон `surface`, активный пункт — фон `accent` @ 10% и текст `accent`, радиус `radiusButton`.
*Flutter:* `NavigationBar` через `navigationBarTheme`. *Web:* `.sidebar` / `.sidebar__item--active`.

### 4.6. Пустые состояния

Строго три элемента по центру: иконка Material Symbols 48px цветом `textSecondary`, одна фраза `body` («Заявок пока нет»), под ней одно действие — primary или secondary кнопка («Создать заявку»). Никаких иллюстраций, никаких вторых абзацев.
*Flutter:* общий виджет `EmptyState(icon, text, action)`. *Web:* партиал/компонент `.empty-state`.

### 4.7. Тосты / снекбары

Тёмная плашка `text` (#1A1915) с белым текстом, радиус `radiusButton`, снизу экрана, автоскрытие 4 с, максимум одно действие («Отменить»). Ошибки — та же плашка с иконкой `error`; успех — с иконкой `success`; фон плашки не перекрашиваем. Для блокирующих ошибок — диалог, не тост.
*Flutter:* `SnackBarThemeData` в `ThemeData`. *Web:* единый компонент `.toast`, контейнер один на страницу.

### 4.8. Таблицы админки и диспетчерской

Компактные: высота строки 36–40, текст `bodyDense` (14), паддинг ячеек `s8`/`s12`. Зебра — чётные строки `bg` (#FAF9F5) на белом, границы строк не рисуем, только нижняя граница шапки 1px `border`. Шапка — `caption` semibold, `textSecondary`; сортируемые колонки — стрелка Material Symbols рядом с заголовком, активная сортировка — заголовок цветом `text`. Hover строки — `accent` @ 6%. Числа и суммы — выравнивание вправо, табличные цифры (`font-variant-numeric: tabular-nums`).
*Web:* один компонент таблицы на обе панели. *Flutter (если понадобится):* `DataTable` с темой, но панели — это web.

### 4.9. Фото-плитки «до/после»

Сетка квадратных плиток 3 в ряд (мобайл), gap `s8`, радиус `radiusCard`, обрезка cover. Ярлык «До»/«После» — мини-бейдж `caption` в левом верхнем углу плитки: фон `text` @ 60%, текст белый. Плитка добавления — пунктирная граница `border`, иконка `photo_camera` цветом `textSecondary` (камера-only по ТЗ — без выбора из галереи у мастера). Тап — полноэкранный просмотр со свайпом.
*Flutter:* общий виджет `PhotoGrid(mode: before/after)` у Мастера и в карточке заявки; в Диспетчерской (web) — те же пропорции для экрана проверки.

### 4.10. QR-экран

Максимально утилитарный: кремовый фон `bg`, по центру белая карточка `radiusCard` с QR-кодом (чёрный на белом, без стилизации, без логотипа внутри — надёжность сканирования важнее), под ним `h2`-подпись назначения («Оплата», «Код точки») и `caption`-пояснение. Яркость экрана программно повышается при показе. Кнопка «Поделиться/Закрыть» снизу.
*Flutter:* пакет `qr_flutter`, цвета кода — чёрный/белый константами (единственное разрешённое исключение из токенов, т.к. это машиночитаемая графика).

## 5. Тёмная тема

**НЕ делаем в MVP.** Одна светлая тема — экономия времени. В коде не закладываем `darkTheme` и не пишем условий `isDark`; появится вместе с финальным дизайном владельца. Единственное требование: не использовать «чистые» системные цвета в обход токенов, тогда тёмная тема позже добавится расширением токен-файла.

---

## 6. Реализация: всё через токены

**Это главное правило гайда: весь стиль через токены, ноль хардкода цветов.** Тогда финальный редизайн владельца = замена значений в одном-двух файлах, без правок экранов.

### 6.1. Flutter (Клиент, Мастер)

- Один файл `design_tokens.dart` в shared-пакете: все цвета, радиусы, отступы, текстовые стили — константами (`AppColors.accent`, `AppRadius.card`, `AppSpacing.s16`, `AppText.h1`).
- Один `ThemeData` (`app_theme.dart`), собранный только из этих констант: `colorScheme`, `textTheme`, `filledButtonTheme`, `outlinedButtonTheme`, `inputDecorationTheme`, `cardTheme`, `snackBarTheme`, `navigationBarTheme`, `chipTheme`.
- В коде экранов запрещены: `Color(0xFF...)`, `Colors.*` (кроме `Colors.transparent`), числовые радиусы и `EdgeInsets` с числами вне шкалы. Правило проверяем на код-ревью; желательно линт-правило на `Color(0x`.
- Оба приложения импортируют один и тот же токен-пакет — стили Клиента и Мастера не могут разъехаться.

### 6.2. Web (Диспетчерская, Админка, лендинги)

- CSS-переменные в `:root` в одном файле `tokens.css`, подключаемом всеми web-продуктами:

```css
:root {
  --bg: #FAF9F5;         --surface: #FFFFFF;
  --text: #1A1915;       --text-secondary: #6E6B63;
  --accent: #C15F3C;     --accent-hover: #A84E2F;
  --success: #7D9B76;    --warning: #D4A27F;
  --error: #B3563E;      --border: #E8E5DD;
  --radius-card: 12px;   --radius-button: 8px;  --radius-chip: 999px;
  --s4: 4px; --s8: 8px; --s12: 12px; --s16: 16px; --s24: 24px; --s32: 32px;
}
```

- В стилях компонентов — только `var(--...)`. Hex встречается в проекте ровно один раз — в `tokens.css`.
- UI-фреймворк панелей настраивается маппингом на эти переменные (например, тема Ant/MUI/Tailwind-конфиг читает те же значения), а не собственной палитрой.

## 7. Что запрещено

- **Градиенты** — любые, включая «лёгкие» на кнопках и лендинге.
- **Кастомные иллюстрации** — рисунки, 3D, стоковые персонажи, лотти-анимации.
- **Анимации сложнее стандартных переходов** — только дефолтные переходы платформы/фреймворка (навигация, ripple, появление снекбара). Никаких parallax, конфетти, скелетон-шиммеров, анимированных графиков.
- **Больше одного акцентного цвета** — семантические цвета (успех/предупреждение/ошибка) акцентом не считаются, но использовать их как декоративные нельзя.
- **Эмодзи в UI** — ни в кнопках, ни в пустых состояниях, ни в пушах-шаблонах; только текст и Material Symbols.
- И повторим: **хардкод цветов/радиусов/отступов вне токен-файлов** — блокер на ревью.
