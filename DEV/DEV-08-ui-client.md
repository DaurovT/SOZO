# DEV-08. UI-спецификация приложения «Клиент» (Flutter)

**Продукт:** USTAPRO / SOZO — мобильное приложение «Клиент» (iOS/Android, Flutter) + веб-карточка заявки W-01…W-05.
**Основание:** PRD-01 (что делает каждый экран — источник истины по функциям) и DEV-06 (токены, компоненты, статус-бейджи — источник истины по стилю). Этот документ отвечает на вопрос «как экран собран и чем наполнен», не повторяя продуктовую логику PRD.
**Назначение:** Flutter-разработчик открывает спецификацию экрана и собирает его без вопросов. Владелец позже перерисует дизайн заменой значений токенов — поэтому здесь нет ни одного «сырого» цвета/размера, только имена токенов и компонентов DEV-06.
**Дата:** июль 2026

Обозначения: `accent`, `surface`, `s16`, `radiusCard`, `h1`, `body`, `caption` — токены DEV-06 §2–3; «primary/secondary/destructive-кнопка», «карточка заявки (OrderCard)», «статус-бейдж (`statusColor`)», «EmptyState», «PhotoGrid», «QR-экран», «тост» — компоненты DEV-06 §4. Иконки — только Material Symbols (outlined), имя иконки указывается в `code`.

## 1. Общие принципы наполнения

**Язык и словарь.** Интерфейс — русский и узбекская латиница. Все строки — только через словарь i18n (ARB-файлы `intl_ru.arb` / `intl_uz.arb`), ключи вида `orderCard.status.enRoute`, `create.slot.urgentTitle`. Хардкод текста в виджете — блокер на ревью, как хардкод цвета. Плейсхолдеры дат/сумм/имён — через параметры ICU (`{sum}`, `{time}`, plural-формы для «2 заявки / 5 заявок»). Смена языка в C-30 перерисовывает приложение без перезапуска.

**Тон текстов.** Коротко и по-человечески, глаголом о событии: «Мастер выехал», «Смета готова», «Не успели за 3 часа — срочность не тарифицируем». Запрещены канцелярит («Статус изменён на…», «Осуществляется обработка»), КАПС, восклицательные знаки в системных текстах, эмодзи (DEV-06 §7). Кнопки — глагол действия: «Вызвать мастера», «Согласен», «Оплатить», не «ОК»/«Далее» там, где можно назвать действие.

**Деньги.** Всегда «1 250 000 сум»: разряды — неразрывными пробелами, без копеек, округление до 100 сум, слово «сум» после суммы (не UZS). Вилка — «от 150 000 до 300 000 сум» или коротко «от 150 000 сум». Отрицательные значения (зачёт, сторно) — «−80 000 сум» с минусом, цветом `success`, если это выгода клиента. Суммы — табличными цифрами (`tabular-nums`), выравнивание вправо в таблицах позиций.

**Даты и время.** Относительный формат, Asia/Tashkent: «сегодня 16:00–18:00», «завтра с 10:00», «25 июля», «через 15 мин», «~16:40» для прогнозов. Полная дата с годом — только в актах и истории старше года. Никаких «2026-07-30T11:00».

**Обязательные состояния каждого экрана** (без исключений, проверяется чек-листом §6):
- **Загрузка** — скелетоны: серые плашки `border` формы будущего контента (без шиммер-анимации — DEV-06 §7), для списков 3–5 плашек-карточек.
- **Пусто** — компонент EmptyState: иконка 48 `textSecondary` + одна фраза `body` + одно действие. Готовые тексты — в спецификациях экранов.
- **Ошибка** — та же композиция EmptyState: иконка `error_outline`, фраза «Не удалось загрузить» (или специфичный текст), secondary-кнопка «Повторить».
- **Офлайн** — кешированные данные + закреплённый баннер сверху: плашка `warning` @ 12%, иконка `cloud_off`, текст `caption` «Нет соединения. Показаны сохранённые данные»; действия, требующие сети (создание, санкции, оплата), — disabled с пояснением.

**Фото.** Плитки PhotoGrid: сетка 3 в ряд, соотношение области 3:2 у одиночных превью, gap `s8`, радиус `radiusCard`, обрезка cover; ярлыки «До»/«После» по DEV-06 §4.9. Тап по любой плитке — полноэкранный просмотр (чёрный фон, свайп между фото, счётчик «2 из 5», закрытие свайпом вниз). Загрузка фото — прогресс-оверлей на плитке, ошибка — иконка `refresh` на плитке, ретрай поштучно.

**Главное действие.** На экране ровно одна primary-кнопка, всегда закреплена внизу (прижата к нижнему краю поверх скролла, отступ `s16`, safe area). Всё второстепенное — secondary или текстовые ссылки. Если главного действия нет (просмотровые экраны) — нижней кнопки нет вовсе.

**Формы.** Лейбл сверху, ошибка под полем цветом `error` без «прыжков» вёрстки (DEV-06 §4.4). Валидация — на blur и на сабмите; primary-кнопка активируется, когда форма валидна (не «жмётся и ругается»). Клавиатура — правильный тип (`phone`, `number`), кнопка не перекрывается клавиатурой.

## 2. Навигационный каркас

### 2.1. Таббар (контекст B2C)

Нижний `NavigationBar` по DEV-06 §4.5, 4 вкладки:

| Вкладка | Иконка | Экран | Примечание |
|---|---|---|---|
| Главная | `home` | C-06 | корень стека создания заявки и активной заявки |
| История | `history` | C-24 | стек: C-24 → C-25 → C-26/C-22/C-23 |
| Техника | `kitchen` | C-28 | **фаза 2**; в MVP вкладка не рендерится (таббар из 3), место зарезервировано feature-флагом |
| Профиль | `person` | C-30 | стек: C-30 → C-29/C-05/C-04/C-23 |

В B2B-контекстах таббар собирается по роли (PRD-01 §1.3): сотрудник — Главная (C-31)/Профиль; рук. точки — Главная/Заявки (C-35)/Лимиты (C-38)/Отчёты (C-39)/Профиль (5-я вкладка «Профиль» допустима); рук. организации — Дашборд (C-40)/Утверждения (C-41, с бейджем-счётчиком `accent`)/Финансы (C-44)/Отчёты (C-47)/Профиль; владелец — Дашборд (C-48)/Профиль. Бейдж на вкладке — точка/число `accent` на иконке.

### 2.2. Стек навигации

- Флоу создания заявки — 3 шага C-07 → C-10 → C-13 (v2.25; C-08/C-09 объединены с C-07, C-12 — с C-10, чек-лист C-11 — bottom-sheet шага C-10) — один модальный стек поверх таббара: закрытие крестиком с любого шага → диалог «Черновик сохранится» (черновик переживает убийство процесса — PRD-01 §6). Возврат назад по шагам сохраняет введённое.
- C-14 (активная заявка) — push в стек «Главной»; санкционные экраны C-15/C-16/C-17/C-18 открываются поверх C-14 (полноэкранные, не bottom-sheet — юридически значимые решения требуют полного контекста); мини-экран C-50 (детали адреса) — тоже поверх C-14.
- Финальная цепочка: C-19 → C-20 (оплата) → C-21 «Спасибо» (оценка + чаевые одним экраном, v2.25) → возврат на C-06 c тостом «Спасибо! Заявка закрыта».
- Смена контекста (C-05) сбрасывает весь стек и пересобирает таббар.

## 3. Поэкранная спецификация

Формат блока: **Композиция** (сверху вниз), **Элементы** (блок → компонент DEV-06 + содержимое), **Наполнение** (обязательные данные, форматы, готовые тексты), **Поведение** (интеракции, валидация). Состояния загрузки/пустоты/ошибки/офлайна описываются только там, где отличаются от общих правил §1.

### 3.1. Онбординг и вход (C-01…C-05)

#### C-01. Splash / язык (онбординг-слайды удалены, v2.25)
**Композиция:** логотип по центру (`bg`) → переключатель языка → primary «Начать» (→ C-02). Онбординг-слайдов нет (ТЗ §17.17 п.1): ценность показывают пустые состояния, после выбора языка — сразу вход по телефону.
**Элементы:** логотип — единственное изображение-исключение (ассет бренда); сегмент-переключатель «Русский / Oʻzbekcha» — два чипа `radiusChip`, активный — фон `accent` @ 12%, текст `accent`.
**Наполнение:** версия приложения `caption` внизу. Блокирующий экран force update: иконка `system_update`, «Обновите приложение, чтобы продолжить», primary «Обновить» (в стор).
**Поведение:** выбор языка мгновенно переключает строки и сохраняется в профиль после входа; активная сессия — сразу переход в контекст; ошибка проверки версии — retry.

#### C-02. Вход по телефону
**Композиция:** app bar без заголовка → `h1` «Вход» → поле телефона → primary «Получить код» → ссылка «Не могу войти».
**Элементы:** поле формы DEV-06 §4.4 с маской «+998 XX XXX-XX-XX», префикс +998 несъедаемый, клавиатура phone; ссылка «Не могу войти» — текст `accent`, открывает bottom-sheet с телефоном поддержки (кнопка звонка).
**Наполнение:** лейбл «Номер телефона», подпись под полем `caption` «Отправим SMS с кодом подтверждения». Ошибки: «Не удалось отправить код, попробуйте позже» (тост), «Аккаунт заблокирован, обратитесь в поддержку» (диалог с кнопкой звонка). Sheet поддержки: «Смена номера — только через поддержку. Позвоните нам: +998 …».
**Поведение:** кнопка активна при 9 введённых цифрах; на тап — спиннер в кнопке, поле блокируется; троттлинг — кнопка disabled с таймером «Повторно через 0:47»; офлайн — кнопка disabled + баннер.

#### C-03. Ввод OTP + согласия (объединён с C-04, v2.25)
**Композиция:** app bar «назад» → `h1` «Код из SMS» → подпись с номером → поле кода → таймер/повтор → блок согласий (только новые пользователи: чекбокс 1 обязательный + чекбокс 2 маркетинг) → (primary не нужна — сабмит по вводу).
**Элементы:** подпись `body` «Отправили код на +998 90 ···-··-45» + ссылка «Изменить номер» (`accent`, назад на C-02); поле кода — 4–6 ячеек `surface` с границей `border`, фокус `accent`; таймер `caption` «Отправить повторно через 0:59» → по истечении ссылка «Отправить код повторно»; чекбоксы согласий — стандартные, активные `accent`, тексты `body` со встроенными ссылками `accent` на полные документы (как C-04).
**Наполнение:** ошибка «Неверный код, осталось попыток: 2» под полем цветом `error`; исчерпание — диалог «Слишком много попыток. Попробуйте через 10 минут»; чекбокс 1 — «Согласен на обработку персональных данных ([политика](…))»; чекбокс 2 — «Согласен получать новости и предложения. Сервисные уведомления о заявках приходят всегда»; подпись `caption` «Отписаться можно в любой момент в профиле».
**Поведение:** авточтение SMS (SMS Retriever) — код проставляется и сабмитится сам; ручной ввод последней цифры — автосабмит; при ошибке ячейки очищаются, фокус в первую; для нового пользователя вход завершается только при отмеченном чекбоксе 1 (иначе подсказка под чекбоксом, код не сгорает); чекбокс 2 по умолчанию выключен; для существующего пользователя блок согласий не показывается.

#### C-04. Согласия (объединён с C-03, v2.25 — в онбординге чекбоксы на экране OTP; экран остаётся для пересмотра согласий из C-30 и при изменении текстов)
**Композиция:** app bar «Согласия» → текст-вступление → чекбокс 1 (обязательный) → чекбокс 2 (маркетинг) → primary «Продолжить».
**Элементы:** чекбоксы — стандартные, активные `accent`; тексты чекбоксов `body` со встроенными ссылками `accent` на полные документы (открываются in-app webview/экран текста).
**Наполнение:** чекбокс 1 — «Согласен на обработку персональных данных ([политика](…))»; чекбокс 2 — «Согласен получать новости и предложения. Сервисные уведомления о заявках приходят всегда»; подпись `caption` «Отписаться можно в любой момент в профиле».
**Поведение:** «Продолжить» активна только при чекбоксе 1; чекбокс 2 по умолчанию выключен; тексты кешируются для офлайна.

#### C-05. Выбор роли/контекста
**Композиция:** app bar «Кто вы сегодня?» → список карточек контекстов → чекбокс «Запомнить выбор».
**Элементы:** карточка контекста — `surface`, `radiusCard`, паддинг `s16`: иконка роли (`person` — личный, `storefront` — точка, `apartment` — организация, `visibility` — владелец), заголовок `body` semibold, подзаголовок `caption`; справа — бейдж-счётчик `accent` (ожидающие утверждения/активные заявки).
**Наполнение:** «Личный аккаунт» / «Аптека №12, ул. Навои — Сотрудник» / «Сеть „Доривор“ — Руководитель». Пусто (привязки удалены): EmptyState `no_accounts` «Нет доступных ролей» + secondary «Позвонить в поддержку».
**Поведение:** тап — вход в контекст, пересборка таббара; «Запомнить выбор» — следующий вход сразу в контекст; 403 от API в любом контексте — выброс сюда с тостом «Доступ изменён».

### 3.2. B2C: главный экран и создание заявки (C-06…C-13)

#### C-06. Главный экран B2C
**Композиция:** app bar (логотип слева, без заголовка) → баннер долга (если есть) → карточка активной заявки (если есть) → primary-зона «Вызвать мастера» → карточка «Повторить» (если есть закрытые заявки, v2.25) → баннер «Аварийная ситуация?» → сетка категорий → карточка «Отложенные рекомендации» (если есть) → таббар.
**Элементы:** карточка активной заявки — OrderCard: № + статус-бейдж `statusColor`, категория/адрес `body`, строка `caption` «окно сегодня 16:00–18:00 · Мастер Алишер»; primary «Вызвать мастера» — крупная, высота 48+, иконка `handyman`; аварийный баннер — карточка с левой полосой `error` 3px (как аварийная OrderCard), иконка `emergency_home`, текст «Аварийная ситуация? Мастер выедет немедленно», вся кликабельна; категории — сетка 2×N плиток `surface` `radiusCard`: иконка 32 (`water_drop` сантехника, `bolt` электрика, `mode_fan` кондиционеры, `door_front` двери/замки…) + подпись `body`; баннер долга — плашка `error` @ 12%, текст «Оплатите задолженность 120 000 сум», кнопка «Оплатить»; карточка «Повторить» (v2.25, ТЗ §17.17 п.2) — `surface` `radiusCard`, иконка `replay` `accent`: заголовок `body` semibold «Повторить: чистка кондиционера», подзаголовок `caption` «мастер Алишер · ул. Навои 12» + шеврон.
**Наполнение:** приветствия и лишние тексты не нужны — экран сразу про действие. Отложенные рекомендации: `caption` «У вас 2 отложенные рекомендации мастера» + шеврон. Пусто = норма (нет активной заявки — просто нет карточки).
**Поведение:** pull-to-refresh; тап по категории → C-07 с предвыбором; тап по карточке «Повторить» → bottom-sheet выбора слота (чипы окон как C-10) → primary «Отправить» — повтор заявки в 2–3 тапа (работы, адрес и детали — из последней закрытой; тот же мастер при доступности, иначе обычное распределение); при долге создание заблокировано (тап по «Вызвать мастера» → диалог о долге с кнопкой оплаты), аварийный баннер остаётся активным (правила PRD C-06); офлайн — кеш + баннер, «Вызвать мастера» disabled.

#### C-07. Шаг 1 «Что сломалось» (объединён с C-08, C-09 — v2.25; шаг 1 из 3)

### 3.3. B2C: жизнь заявки (C-14…C-23, C-50)

#### C-14. Активная заявка
**Композиция:** app bar «Заявка Z-2026-000123» (назад, справа иконка `flag` «Пожаловаться») → баннер события (условный) → статус-трекер → карта ETA (после «Выехал») → карточка мастера → карточка паузы (условная) → индикатор сессий (этапная) → состав работ и вилка → PhotoGrid фото заявки → быстрые сообщения → ряд secondary-действий → primary «Позвонить диспетчеру».
**Элементы:**
- Статус-трекер — вертикальный степпер: пройденные шаги — иконка `check_circle` `success`, текущий — статус-бейдж `statusColor` + время перехода `caption`, будущие — `textSecondary`. Цепочка B2C: Новая → Оценена → Назначена → Мастер выехал → В работе → Выполнена → Проверена → Закрыта (без «На утверждении/Утверждена»).
- Карточка мастера — `surface` `radiusCard`: аватар (круг `radiusChip` 48), имя `body` semibold, строка `caption` «★ 4,9 · 312 работ», прогноз `body` «Завершает предыдущий заказ, приедет ~16:40»; телефона мастера нет — только звонок через диспетчера.
- Карта ETA — вью ~180 с пином мастера и адресом, подпись «Будет через ~15 мин».
- Карточка паузы — статус-бейдж остаётся терракотовым + второй бейдж `warning`: «Ожидание материалов» / «Технологический перерыв» / «Заблокировано третьей стороной», текст `caption` «Следующая попытка: завтра 10:00».
- Индикатор сессий — чип-строка «Сессия 2 из 3 · следующая — пятница 10:00», тап → C-18.
- Быстрые сообщения — горизонтальные чипы-шаблоны: «Я задерживаюсь», «Позвоните мне», «Домофон не работает» (MVP вместо чата).
- Действия — secondary «Перенести», destructive «Отменить заявку» (DEV-06 §4.1).
**Наполнение:** баннеры событий (по одному сверху, приоритет по свежести): «Мастер назначен — уточните детали для мастера» + кнопка «Указать» → C-50 (v2.25; висит до заполнения или фиксации деталей диспетчером); «Мастер заменён — к вам едет Бахтиёр, будет к 17:10»; «Приносим извинения, новое время ~17:30» (сдвиг прогноза, `warning` @ 12%); «Появилось окно сегодня 16:00–18:00» + primary «Подтвердить» в баннере (лист ожидания); «Не успели за 3 часа — срочность не тарифицируем» (`success` @ 12%). Состав работ — позиции с ценами и вилкой «от–до» итога.
**Поведение:** pull-to-refresh + пуш-обновления; «Перенести» — bottom-sheet со слотами; при <2 ч до окна или 3-й перенос — sheet объясняет: «Перенести уже нельзя — можно только отменить»; диалог переноса предупреждает «Мастер будет назначен заново»; «Отменить» — диалог с деньгами: «До окна больше 2 часов — бесплатно» / «Мастер уже в пути — оплачивается выезд 50 000 сум» / «Работы начаты — оплачивается выезд и фактически сделанное»; офлайн — кешированное состояние + баннер, поллинг при восстановлении; баннеры санкций («Подтвердите стоимость») ведут в C-15/C-16/C-17.

**Композиция:** app bar «Подтвердите стоимость» (без «назад»-свайпа мимо решения — закрытие возвращает в C-14 с висящим баннером) → плашка контекста → таблица позиций → блок запчастей → итог → примечание о материалах → primary «Согласен» → secondary «Отказываюсь» → текстовая «Позвонить диспетчеру».
**Элементы:**
- Плашка контекста — `accent` @ 12%, иконка `assignment`: «Мастер Алишер составил точную смету. Работы начнутся после вашего подтверждения».
- Таблица позиций — строки: название `body`, «2 шт × 90 000» `caption`, сумма справа semibold, tabular-nums.
- Блок запчастей — на позиции с запчастью чип ценового уровня: «Эконом» / «Стандарт» / «Премиум» (чип `border`/`textSecondary`) + название и цена конкретной детали: «Смеситель Vidima, стандарт — 420 000 сум».
- Строка «Минимальный заказ +50 000 сум» — если добивка; строка зачёта осмотра «Осмотр зачтён: −80 000 сум» (`success`).
- Дельта к вилке (v2.25, ТЗ §17.17 п.4): если итог выше показанной при создании вилки — плашка `warning` @ 12%: «Смета выше первоначальной оценки на 120 000 сум — вот почему» + **обязательный блок доказательств**: по каждой подорожавшей позиции — фото мастера (PhotoGrid) и причина `body` («Труба за плиткой оказалась чугунной — нужен другой переход»); паттерн перенесён из C-16; без фото и причины по каждой такой позиции мастер не может отправить смету на подтверждение (валидация на стороне мастера, клиент неполную смету не видит).
- Итог — `h1` «Итого работы: 540 000 сум»; примечание `caption` «Материалы — по чекам и каталогу, добавятся по факту».
**Наполнение:** тексты кнопок ровно «Согласен» и «Отказываюсь» (юридические формулировки аудита); диалог отказа: заголовок «Отказаться от работ?», текст «Работы не начнутся. Оплачивается только выезд и диагностика — 50 000 сум», кнопки destructive «Отказаться» / «Вернуться».
**Поведение:** «Согласен» — спиннер, фиксация в аудит (кто, когда, сумма, устройство), возврат в C-14 с тостом «Смета подтверждена, мастер приступает»; для этапной работы после «Согласен» сразу открывается C-18 (слоты сессий подтверждаются вместе со сметой); «Отказываюсь» → завершение → C-19/C-20; ошибка отправки — retry-диалог «Мастер ждёт на объекте — повторите»; офлайн — обе кнопки disabled + баннер «Решение можно принять только онлайн» (анти-подделка согласий).

#### C-16. Вынужденная доп-работа
**Композиция:** app bar «Требуется ваше решение» → плашка-предупреждение → PhotoGrid фото проблемы → описание → радио-варианты → блок «Если отказаться» → primary «Согласен с вариантом…» → destructive «Отказаться от доп-работ» → «Позвонить диспетчеру».
**Элементы:** плашка — `error` @ 12%, иконка `warning`: «Без этой работы завершить заявку невозможно» (визуально и текстово отличается от апсейла C-17 — экраны не спутать); радио-карточки вариантов — `surface` `radiusCard`, граница выбранной `accent` 1.5px: «Минимальный — безопасная времянка · 180 000 сум» / «Полный — полное устранение · 460 000 сум», под каждым `caption` с описанием; блок отказа — `caption` `textSecondary`: «При отказе мастер выполнит консервацию (безопасное отключение) — 60 000 сум».
**Наполнение:** текст primary-кнопки подставляет выбор: «Согласен с вариантом „Минимальный“»; диалог отказа: «Отказаться от доп-работ?» — «Это может быть небезопасно. Мастер выполнит консервацию, заявка завершится частично. В акте будет отмечено, что вы предупреждены», кнопки destructive «Отказаться» / «Вернуться».
**Поведение:** primary disabled, пока вариант не выбран; решения — только онлайн (как C-15); согласие → C-14 (работа продолжается, доп-смета в составе работ); отказ → консервация → C-19 с пометкой «Выполнена частично»; ошибка отправки — retry, мастер видит «ожидание».

#### C-17. Апсейл (рекомендация мастера)
**Композиция:** app bar «Рекомендация мастера» → плашка «это не обязательно» → PhotoGrid → позиции с ценами → комментарий мастера → primary «Принять» → secondary «Отложить» → текстовые «Отклонить» и «Пожаловаться на навязывание».
**Элементы:** плашка — `border` @ 50% (нейтральная, не тревожная — контраст с C-16): иконка `lightbulb`, «Это рекомендация. Отказ никак не влияет на текущую работу»; комментарий мастера — цитата `body` на `surface`: «Подводка на ладан дышит — лучше заменить, пока разобрано».
**Наполнение:** позиции с точными ценами (не вилка); «Отложить» — подпись `caption` «Сохраним в ваших рекомендациях — вернётесь, когда удобно».
**Поведение:** «Принять» → утверждённая доп-смета, тост «Мастер сделает сейчас», → C-14; «Отложить» → список рекомендаций (C-06/C-28); «Отклонить» — без диалога-уговоров (анти-давление), просто закрытие; «Пожаловаться на навязывание» → C-23 с предвыбранной причиной; офлайн — решения disabled.

#### C-18. План сессий этапной работы
**Композиция:** app bar «План визитов» → правило-плашка → таймлайн сессий → выбор слотов несогласованных сессий → primary «Подтвердить план» → «Позвонить диспетчеру».
**Элементы:** таймлайн — вертикальный степпер: «Сессия 1 — среда, 30 июля, 10:00–12:00» (пройденная — `success`), между сессиями пометка `caption` «пауза 24 ч – 7 дней»; выбор слота — чипы окон как в C-10, но отфильтрованные под ленту того же мастера; правило-плашка `border` @ 50%: «Цена — за работу целиком, выезды всех визитов включены. Оплата после последнего визита».
**Наполнение:** нет слотов в допустимом окне — карточка вариантов планировщика: «Перенести всю работу на даты, где цепочка складывается» / «Запросить сверхурочный слот»; кнопка «Перенести сессию» у каждой будущей сессии (в пределах окна паузы).
**Поведение:** «Подтвердить план» активна только при выбранных слотах всех сессий (инвариант «этап 1 не начнётся без подтверждённой цепочки»); подтверждение → C-14, между сессиями пауза-бейдж «Технологический перерыв».

#### C-19. Итог выполненной заявки
**Композиция:** app bar «Заявка выполнена» → блок приёмки (код) → PhotoGrid «До/После» → таблица работ → блок материалов → блок «Список покупки» (разворачиваемый) → строки скидок/зачёта → итог → гарантия → primary «Оплатить» → ряд текстовых действий («PDF-акт», «Оспорить», «Пожаловаться»).
**Элементы:**
- Блок приёмки (v2.25, ТЗ §17.17 п.3): при предстоящей онлайн-оплате — карточка `accent` @ 12% с текстом «Оплата в приложении подтверждает приёмку — отдельного действия не нужно» (кнопки и кода нет); при наличных — «Код приёмки: **4 8 3 1**» крупно (`h1`, tabular), текст `caption` «Назовите код мастеру — или подтвердите здесь», secondary «Подтверждаю приёмку» (единый механизм с C-34; код — для наличных и телефонного канала).
- PhotoGrid — режим before/after с ярлыками «До»/«После» (DEV-06 §4.9), «в процессе» — третья группа при наличии.
- Таблица работ — позиция, кол-во, цена, сумма (tabular, суммы вправо).
- Материалы — «Запчасти» (позиции + мини-плитки фото чеков/накладных, тап — просмотр) и «Расходники» (по фикс-каталогу, без чеков, `caption` пояснение «по каталогу компании»).
- «Список покупки» — разворачиваемая секция (иконка `receipt_long`): позиции, количество, сумма по чеку партнёрского магазина.
- Строки: «Скидка по промокоду: −54 000 сум», «Осмотр зачтён в стоимость работ: −80 000 сум» (`success`).
- Итог `h1` «К оплате: 1 250 000 сум»; гарантия — чип `success` @ 12%, иконка `verified_user`: «Гарантия 30 дней — до 29 августа».
- «Выполнена частично» — бейдж `warning` + строка «Выполнена консервация. Вы отказались от доп-работ — это отмечено в акте».
**Наполнение:** если оплата уже проведена на месте — вместо primary «Оплатить» бейдж «Оплачено · Payme» и primary становится «Оценить работу» (→ C-21); «PDF-акт» доступен после закрытия (с QR на онлайн-версию), до закрытия — скрыт; «Оспорить» — виден в окне 72 ч.
**Поведение:** «Подтверждаю приёмку» (наличные) — спиннер, блок сменяется на «Приёмка подтверждена» `success`; при онлайн-оплате приёмка фиксируется успешным платежом на C-20 (v2.25); фото по signed URL, ошибка — поштучный ретрай; статус «дорабатывается» (возврат диспетчером): баннер `warning` «Мастер устраняет замечания — мы сообщим»; тап «Оплатить» → C-20.

#### C-20. Оплата (чаевые перенесены в C-21 «Спасибо», v2.25)
**Композиция:** app bar «Оплата» → сумма → кнопки способов → блок «QR с экрана мастера» → блок «Наличные» → primary = выбранный способ.
**Элементы:**
- Сумма — `h1` «1 250 000 сум», под ней `caption` «работы + материалы − скидка».
- Способы — вертикальный список кнопок-карточек `surface` `radiusCard` (лого провайдера + название): «Payme», «Click», «Uzum» (фаза 2, скрыт feature-флагом), «Банковская карта»; тап → мерчант-SDK/redirect.
- «Отсканировать QR с экрана мастера» — secondary с иконкой `qr_code_scanner`.
- Наличные — плашка `border` @ 50%: «Наличные — передайте мастеру, он зафиксирует оплату в своём приложении».
**Наполнение:** подпись под способами `caption` «Оплата в приложении подтверждает приёмку работ» (v2.25, ТЗ §17.17 п.3); экран ожидания callback: спиннер + «Проверяем оплату — не закрывайте экран»; неуспех: EmptyState `error_outline` «Оплата не прошла» + primary «Попробовать ещё раз» + secondary «Другой способ»; статус возврата при споре — строка «Возврат: в обработке у Payme».
**Поведение:** двойной тап по способу игнорируется (идемпотентность + блокировка UI); успешная онлайн-оплата одновременно фиксирует приёмку (отдельного тапа не требуется); успех → C-21 «Спасибо» (оценка + чаевые) → C-06 с тостом «Спасибо! Заявка закрыта»; офлайн — онлайн-способы disabled, остаются QR и наличные (fallback).

#### C-21. Оценка + чаевые — экран «Спасибо» (объединён с блоком чаевых C-20, v2.25)
**Композиция:** app bar «Спасибо» → карточка мастера (аватар, имя, № заявки) → 5 звёзд → чипы чаевых (при онлайн-оплате) → поле комментария → предложение «Запомнить мастера» (условное) → primary «Отправить» → текстовая «Позже».
**Элементы:** звёзды — иконки `star` 44px, активные `accent`, тап-зона ≥44; чипы чаевых — пресеты «10 000», «20 000», «50 000», «Своя сумма» (поле), заголовок секции `h2` «Поблагодарить мастера?», подпись `caption` «Чаевые целиком получает мастер»; комментарий — многострочное поле, плейсхолдер «Что понравилось или не понравилось?»; «Запомнить мастера» — появляется после выбора 4–5 звёзд: строка со Switch «Запомнить мастера — будем предлагать его первым».
**Наполнение:** окно 72 ч истекло — EmptyState `schedule` «Окно оценки закрыто» (кнопка не нужна); при оплате наличными секция чаевых не показывается.
**Поведение:** одна кнопка «Отправить» — оценка и чаевые уходят вместе (ТЗ §17.17 п.3); чип не выбран — чаевых нет, отдельной кнопки «Без чаевых» и повторных вопросов нет; primary активна после выбора звёзд; оценка 1–2 — комментарий становится обязательным мягко (подпись «Расскажите, что случилось — разберёмся и перезвоним за 2 часа»); отправка → C-06.

#### C-22. Спор («Оспорить»)
**Композиция:** app bar «Оспорить заявку» → сводка заявки (№, сумма) → радио-причины → поле описания → PhotoGrid (опц.) → плашка-последствие → primary «Отправить спор».
**Элементы:** причины из справочника — радио-строки: «Качество работы», «Не согласен с суммой», «Приехал не тот мастер», «Другое»; плашка `border` @ 50%: «Мы заморозим расчёты по заявке и разберёмся. Обычно это занимает до 3 дней».
**Наполнение:** карточка статуса спора (просмотр после отправки): бейдж `error` «Спор», строки «Открыт 26 июля», резолюция — «Решён в вашу пользу: возврат 200 000 сум через Payme» / «Решён в пользу мастера» / «Компромисс: …».
**Поведение:** валидация — причина обязательна, описание ≥ 10 символов; отправка → C-25 со статусом «Спор»; окно 72 ч истекло — вход скрыт (остаётся «Пожаловаться»).

#### C-23. Жалоба
**Композиция:** app bar «Жалобы» → список моих жалоб → primary «Новая жалоба»; форма: радио-типы → поле описания → PhotoGrid (опц.) → связь с заявкой (опц., выбор из списка) → primary «Отправить».
**Элементы:** типы: «Качество работы», «Поведение мастера», «Сроки», «Деньги», «Сервис и диспетчер», «Приложение», «Другое»; карточка жалобы в списке — `surface`: тип `body`, дата `caption`, статус-чип («Новая» — серый, «В работе» — `accent`, «Решена»/«Закрыта» — `success`) + текст резолюции.
**Наполнение:** пусто — EmptyState `sentiment_satisfied` «Жалоб нет — и хорошо»; выбор типа «Деньги» — плашка-подсказка: «Похоже, это спор по заявке. Спор замораживает расчёты» + кнопка «Перейти к спору» (→ C-22).
**Поведение:** отправка — тост «Жалоба зарегистрирована. Ответим в течение 2 часов (8:00–22:00)»; push о смене статуса ведёт в список.

### 3.4. B2C: история, гарантия, профиль (C-24…C-30)

#### C-24. История заявок
**Композиция:** app bar «История» → чипы-фильтры → список OrderCard → (пусто/скелетоны).
**Элементы:** фильтры — горизонтальные чипы «Все», «Активные», «Закрытые», «Споры», «Гарантийные», активный — `accent` @ 12%; карточка — OrderCard по DEV-06 §4.2: «Z-2026-000123» + статус-бейдж, категория и адрес, `caption` «25 июля · 1 250 000 сум · Алишер».
**Наполнение:** пусто — EmptyState `history` «Пока нет заявок» + primary «Вызвать мастера»; телефонные заявки отображаются в общем списке без пометок.
**Поведение:** тап → C-14 (активная) или C-25 (закрытая); pull-to-refresh; бесконечная пагинация (спиннер-строка внизу); офлайн — кеш + баннер.

#### C-25. Карточка закрытой заявки / акт
**Композиция:** app bar «Z-2026-000123» → статус-бейдж + даты → гарантийный блок → PhotoGrid до/после → таблица работ и материалов (как C-19) → канал оплаты → оценка → primary «Проблема вернулась» (в гарантии) → ряд текстовых действий.
**Элементы:** гарантийный блок — карточка `success` @ 12%, иконка `verified_user`: «Гарантия до 29 августа» + прогресс-подпись `caption` «осталось 12 дней»; канал оплаты — строка «Оплачено · наличные мастеру»; оценка — звёзды read-only + комментарий; действия: «Скачать PDF-акт», «Оспорить» (только в окне 72 ч), «Пожаловаться», «Повторить заявку», ссылка на единицу техники (фаза 2, → C-28).
**Наполнение:** гарантия истекла — блок серый (`border`), primary заменяется на «Создать новую заявку» (предзаполненное создание); «Повторить заявку» после платной диагностики — на шаге слота покажется баннер зачёта (C-10).
**Поведение:** «PDF-акт» — загрузка с прогрессом, открытие системным вьювером, в акте QR на онлайн-версию; «Проблема вернулась» → C-26; вход возможен по QR с бумажного акта (deep-link).

#### C-26. Гарантийное обращение
**Композиция:** app bar «Проблема вернулась» → карточка исходной заявки → плашка «бесплатно» → поле описания → PhotoGrid → выбор окна (чипы как C-10) → primary «Отправить».
**Элементы:** плашка — `success` @ 12%, иконка `verified_user`: «Гарантийный ремонт — бесплатно. Приедем в приоритетном порядке»; карточка исходной заявки — компактная OrderCard (№ , категория, дата закрытия).
**Наполнение:** плейсхолдер описания «Что случилось снова?»; подпись `caption` «Диспетчер позвонит в течение 4 часов».
**Поведение:** валидация — описание обязательно; отправка → C-14 гарантийной заявки (смета 0, суммы не показываются, бейдж «Гарантийная» — серый чип рядом со статусом).

#### C-27. Касание «Как дела»
**Композиция:** открывается из push как диалог-экран: иконка категории → вопрос `h2` → primary «Всё отлично» → secondary «Есть проблема».
**Элементы:** вопрос подставляет технику/работу: «Кондиционер работает нормально?»; под кнопками `caption` «Прошло 2 недели после ремонта — проверяем, всё ли в порядке».
**Наполнение:** «Всё отлично» — тост «Отлично! Хорошего дня» и закрытие; «Есть проблема» → C-26 с предзаполненной исходной заявкой.
**Поведение:** закрытие свайпом/крестиком без ответа — допустимо, без последствий и повторных показов.

#### C-28. Моя техника (фаза 2)
**Композиция:** app bar «Моя техника» → список единиц → карточка единицы: фото шильдика → данные → рекомендации → история работ.
**Элементы:** карточка единицы в списке — `surface`: иконка типа (`mode_fan`, `kitchen`, `water_heater`), «Кондиционер Artel 12» `body`, `caption` «установлен 2023 · последняя чистка — май»; рекомендация — карточка с чипом приоритета и ценой: «Пора чистить — прошло 6 месяцев · ~150 000 сум» + primary «Записаться»; история — строки «чистка — май 2026 · 180 000 сум» со ссылками на C-25.
**Наполнение:** пусто — EmptyState `home_repair_service` «Здесь появится техника после первого визита мастера» (без кнопки); «Отписаться от напоминаний» — текстовая ссылка в карточке единицы, один тап.
**Поведение:** «Записаться» → создание заявки сразу с шага слота (C-10), позиция предзаполнена, любимый/закреплённый мастер в приоритете; редактирование данных единицы — форма по полям.

#### C-29. Мои адреса
**Композиция:** app bar «Мои адреса» (иконка `add` справа) → список адресов → (пусто).
**Элементы:** карточка адреса — `surface`: «ул. Навои 12, кв. 45» `body`, `caption` «подъезд 3 · этаж 5 · домофон 45В · лифт есть», чип «Основной» (`accent` @ 12%); свайп/меню — «Изменить», «Удалить».
**Наполнение:** пусто — EmptyState `location_on` «Сохранённых адресов нет» + secondary «Добавить адрес»; форма адреса = поля из C-10.
**Поведение:** удаление — диалог подтверждения; выбор из C-10 возвращает адрес в форму заявки; «Основной» подставляется в новую заявку по умолчанию.

#### C-30. Профиль и настройки
**Композиция:** app bar «Профиль» → карточка аккаунта (имя, телефон) → группа «Настройки» (язык, контекст, PIN/биометрия) → группа «Мои данные» (адреса, жалобы, согласия) → группа «Поддержка» → текстовая «Выйти» → версия.
**Элементы:** строки-настройки `surface`, иконка + название + значение справа + шеврон: «Язык — Русский» (bottom-sheet выбора), «Контекст — Личный» (→ C-05), «PIN и биометрия» (для утверждающих ролей — настройка подтверждения крупных сумм), «Мои адреса» (→ C-29), «Мои жалобы» (→ C-23), «Согласия» (→ C-04; Switch маркетинга — отписка в один тап), «Позвонить в поддержку», «Сменить номер» (экран-инструкция: «Смена номера — через поддержку с подтверждением личности» + кнопка звонка).
**Наполнение:** «Выйти» — destructive-текст, диалог «Выйти из аккаунта?»; версия `caption` `textSecondary` внизу по центру.
**Поведение:** смена языка применяется мгновенно ко всему UI и пишется в профиль (меняет язык SMS/push/документов); переключение маркетингового согласия — без диалогов, тост «Отписали от новостей».

### 3.5. Режим «Сотрудник точки» (C-31…C-34, C-49)

#### C-31. Главный экран сотрудника точки
**Композиция:** app bar «{Аптека №12}» → карточка кода приёмки (условная) → primary-зона «Сообщить о поломке» → список заявок точки (усечённые OrderCard) → карточка «Что делать при аварии» → строка «Мои баллы» (условная) → таббар.
**Элементы:** primary «Сообщить о поломке» — крупная, иконка `report_problem`; усечённая OrderCard — статус-бейдж, категория, `caption` «окно 16:00–18:00 · Алишер» — **без сумм и смет** (настройка организации); карточка кода приёмки — при заявке в статусе «Выполнена»: `accent` @ 12%, «Мастер закончил — подтвердите приёмку», кнопка → C-34; «Что делать при аварии» — карточка с иконкой `emergency_home` → C-33; «Мои баллы» — строка с иконкой `stars` и бейджем баланса «128 000» → C-49 (только при включённой программе).
**Наполнение:** заявка на утверждении — статус «Ждёт утверждения» без суммы; пусто — EmptyState `storefront` «Заявок нет» + акцент на кнопке.
**Поведение:** тап по заявке → усечённый C-14 (без денег, без «Отменить»); апсейлы сотруднику не показываются; офлайн — кеш + баннер.

#### C-32. «Сообщить о поломке»
**Композиция:** один экран: app bar «Сообщить о поломке» → PhotoGrid → поле описания → выбор категории (чипы + «Не знаю») → чек-лист доступа (условный, для категорий с общими зонами) → срочность (радио-карточки) → primary «Отправить».
**Элементы:** точка и адрес предзаполнены (плашка `border` @ 50% «Аптека №12, ул. Навои 12»); срочность — три радио-карточки: «Обычная», «Аварийная» (иконка `emergency_home` `error`, подпись «Мастер выедет немедленно» + ссылка «что считается аварией»), «Срочно» (`bolt`, «+30% к работам, ближайший свободный мастер»); чек-лист доступа — те же вопросы и дата-пикер, что C-11.
**Наполнение:** фото обязательно предложено — при пустом PhotoGrid на сабмите мягкий диалог «Добавите фото? Мастеру будет проще подготовиться» с кнопками «Добавить» / «Отправить без фото» (для аварийной — диалога нет); после отправки: если авто-старт в лимите — тост «Заявка принята, ищем мастера», если сверх лимита — тост «Заявка отправлена на утверждение руководителю».
**Поведение:** черновик сохраняется при ошибке; детект дублей — диалог «Похожая заявка уже есть» («Открыть её» / «Всё равно создать»); анти-дробление — сотрудник видит статус «На проверке у диспетчера» без объяснения механики; после аварийной отправки автоматически открывается C-33.

#### C-33. Инструкция при аварии
**Композиция:** app bar «Что делать сейчас» → шаги-карточки с фото → primary «Позвонить диспетчеру».
**Элементы:** шаг — карточка `surface`: номер шага в круге `accent`, текст `body` «Перекройте кран холодной воды», фото из паспорта объекта (плитка 3:2, «кран — в подсобке за стеллажом»); без паспорта — общая инструкция без фото.
**Наполнение:** тексты по категориям аварий: вода — «Перекройте кран → уберите технику из воды»; электрика — «Отключите автомат в щитке → не трогайте оголённые провода»; газ — «Перекройте кран → откройте окна → позвоните 104».
**Поведение:** экран кешируется целиком (офлайн-доступ — авария может быть с обрывом сети); открывается автоматически после создания аварийной заявки.

#### C-34. Код приёмки
**Композиция:** app bar «Приёмка работ» → крупный код → подпись → PhotoGrid «После» (беглая проверка) → primary «Подтвердить приёмку в приложении» → текстовые «Обновить код» и «Не принимаю работу».
**Элементы:** код — 4 цифры `h1`-крупнее (48+), tabular, с разрядкой «4 8 3 1», на карточке `surface` `radiusCard` по центру (паттерн QR-экрана DEV-06 §4.10, но с цифрами); подпись `body` «Назовите код мастеру — или подтвердите кнопкой ниже. Это одно и то же»; фото «после» — PhotoGrid read-only, без сумм.
**Наполнение:** «Не принимаю работу» — форма комментария диспетчеру («Что не так?») + отправка, тост «Передали диспетчеру — он свяжется с вами»; после подтверждения — экран-состояние `success`: иконка `check_circle`, «Приёмка подтверждена».
**Поведение:** «Обновить код» — перегенерация с коротким троттлингом; офлайн — показывается последний кешированный код (устная передача работает без сети), кнопка подтверждения disabled; после ввода кода мастером карточка сама обновляется до «Выполнена».

#### C-49. Мои баллы и ваучеры
**Композиция:** app bar «Мои баллы» → карточка баланса с прогрессом → список ваучеров → история начислений → текстовая «Правила программы».
**Элементы:** карточка баланса — `surface` `radiusCard`: «128 000 баллов» `h1`, прогресс-бар до порога (`accent` на треке `border`), подпись `caption` «Ещё 72 000 — и получите ваучер Корзинки на 200 000»; ваучер — карточка: логотип-текст «Korzinka», номинал `h2` «200 000 сум», срок «до 15 сентября», статус-чип («Активен» — `success`, «Погашен» — серый, «Истёк» — серый перечёркнутый); история — строки «Заявка Z-…-321 · +12 400» / сторно «−12 400» (`error`) с датами.
**Наполнение:** пусто — EmptyState `stars` «Баллов пока нет — сообщайте о поломках через приложение»; отрицательный баланс — «−8 000 баллов» + подпись «Спишется из будущих начислений»; предупреждение сгорания — плашка `warning` @ 12% «Программа отключена. Баллы можно обменять до 28 сентября».
**Поведение:** тап по ваучеру — полноэкранный QR по DEV-06 §4.10 (чёрный на белом, авто-яркость, подпись «Покажите на кассе Корзинки»); ваучеры и QR кешируются — работают офлайн; «Правила программы» — текстовый экран.

### 3.6. Режим «Руководитель точки» (C-35…C-39)

#### C-35. Лента заявок точки
**Композиция:** app bar «Заявки точки» → чипы-фильтры (статус/период) → список OrderCard (полные, с суммами) → FAB-паттерн не используем: primary «Сообщить о поломке» внизу.
**Элементы:** OrderCard полный: № + статус-бейдж, категория, `caption` «смета 850 000 сум · Алишер · окно 16:00–18:00»; заявка на утверждении — дополнительный чип `warning` «Ждёт утверждения» и тап ведёт сразу в C-36.
**Наполнение:** заявка выше порога руководителя — чип серый «У руководителя организации» (read-only); пусто — EmptyState `storefront` «Заявок нет» + primary «Сообщить о поломке».
**Поведение:** тап → полный C-14 (с суммами) или C-36; pull-to-refresh, пагинация, офлайн-кеш.

#### C-36. Утверждение сметы / доп-сметы
**Композиция:** app bar «Утверждение» (тип в подзаголовке `caption`) → плашка типа → карточка контекста (точка, мастер, № заявки) → PhotoGrid → таблица позиций → итог → таймер эскалации (условный) → primary «Утвердить» → secondary/destructive «Отклонить» → текстовая «Вопрос диспетчеру».
**Элементы:**
- Плашка типа задаёт тон экрана: обычная смета — `border` @ 50% «Смета по заявке»; доп-смета — `warning` @ 12% «Доп-смета: превышение на 240 000 сум»; **вынужденная** — `error` @ 12%, иконка `warning`, «Без этой работы завершить заявку невозможно» + радио-варианты «Минимальный/Полный» (как C-16) + таймер; **апсейл** — `border` @ 50%, «Рекомендация мастера — не обязательна, автостарта не будет».
- Таймер эскалации (вынужденная) — строка `caption` цветом `warning`: «Ответьте до 14:30 — иначе вопрос уйдёт руководителю организации»; исходная работа при этом продолжается — подпись «Согласованная часть работ не остановлена».
- Таблица позиций — с ценовыми уровнями запчастей (чипы «эконом/стандарт/премиум», как C-15); итог `h1`.
- Для апсейла третья кнопка — secondary «Отложить» (уходит в техдолг точки).
- Критичный дефект — красный флаг: чип `error` «Критично» + подпись «Диспетчер позвонит вам дополнительно».
**Наполнение:** диалог отклонения вынужденной: «Отклонить доп-работу?» — «Мастер выполнит консервацию. Позиция попадёт в техдолг точки с готовой оценкой» — destructive «Отклонить» / «Вернуться»; смета выше порога роли — режим read-only: вместо кнопок плашка «Передано на уровень выше — ждёт руководителя организации»; двойное утверждение — после «Утвердить» экран-состояние «Вы утвердили. Ждёт второго утверждения владельцем» с иконкой `hourglass_top`.
**Поведение:** сумма выше порога повторной аутентификации (по умолчанию 5 000 000 сум) — перед фиксацией системный запрос PIN/биометрии, заголовок «Подтвердите утверждение на 6 400 000 сум»; каждое решение — аудит (кто, когда, сумма, устройство); решения только онлайн; ошибка отправки — retry-диалог; после решения → возврат в C-35/C-41 с тостом «Смета утверждена» / «Отклонено»; режим второго утверждения владельца — те же блоки, primary «Утвердить (второе утверждение)», PIN/биометрия обязательны.

#### C-37. Техдолг точки
**Композиция:** app bar «Техдолг точки» → карточка суммы с разбивкой → чипы-фильтры приоритета → список дефектов → (карточка дефекта: фото → описание → оценка → срок актуальности → действия).
**Элементы:** карточка суммы — «4 200 000 сум» `h1` + строки по приоритетам: «Критичный 1 100 000» (`error`), «Высокий…», «Средний…», «Низкий…»; дефект в списке — карточка: мини-фото, описание `body`, чип приоритета (`statusColor`-логика: критичный `error`, высокий `warning`, остальные серые), «оценка 460 000 сум · актуальна до 20 августа», подсветка возраста «60+ дней» — `caption` `error`; действия в карточке дефекта — primary «Утвердить» (порождает заявку), secondary «Отложить до даты» (дата-пикер), destructive «Отклонить».
**Наполнение:** пусто — EmptyState `task_alt` «Дефектов нет»; истёкшая оценка — чип «Требует переоценки», «Утвердить» disabled; MVP — этот же экран как простой список без сумм-аналитики (feature-флаг).
**Поведение:** «Утвердить» в пределах порога роли — заявка со статусом «Утверждена» появляется в C-35; «Отклонить» — с причиной, дефект остаётся в архиве с пометкой.

#### C-38. Лимиты точки
**Композиция:** app bar «Лимиты и доступ» → карточка лимитов → карточка графика доступа → карточка контакта ТСЖ/УК.
**Элементы:** лимиты — «Лимит на заявку: 500 000 сум» и прогресс-бар месяца: «Израсходовано 640 000 из 1 500 000» (`accent` на `border`; при >90% бар `warning`); график доступа — редактируемые интервалы по дням недели («Пн–Пт 9:00–18:00»); контакт ТСЖ — поля ФИО и телефон с кнопкой звонка.
**Наполнение:** исчерпан лимит — плашка `warning` @ 12% «Лимит исчерпан. До конца месяца все заявки идут на утверждение»; подпись у лимитов `caption` «Лимиты меняет руководитель организации».
**Поведение:** лимиты read-only; график и контакт редактируются руководителем точки (сохранение — тост «Сохранено»).

#### C-39. Отчёты точки
**Композиция:** app bar «Отчёты» → список месяцев → карточка месяца: сводка → primary «Скачать PDF» → «Поделиться».
**Элементы:** карточка месяца — `surface`: «Июль 2026» `h2`, строки `caption` «Заявок: 14 · из них аварийных: 2», «Работы: 3 400 000 · Материалы: 1 200 000», «Списано с абонентки: 2 500 000 · Сверхлимит: 900 000», мини-строка «Техдолг: 4 200 000».
**Наполнение:** пусто — EmptyState `description` «Отчёт появится после первого месяца работы»; генерация — состояние «Отчёт формируется…» со спиннером.
**Поведение:** «Скачать PDF» — прогресс, системный вьювер (в PDF — QR-ссылки на акты); «Поделиться» — системный share sheet.

### 3.7. Режим «Руководитель организации» (C-40…C-47)

#### C-40. Дашборд организации (светофор)
**Композиция:** app bar «{Сеть „Доривор“}» → баннер приостановки (условный) → карточка-сводка → плитка «Центр утверждений» с бейджем → сетка плиток точек → таббар.
**Элементы:** плитка точки — `surface` `radiusCard`: название `body`, индикатор-светофор — **точка-иконка + текстовая подпись** (не только цвет — доступность): `success` + «Всё в порядке» / `warning` + «Заявки в работе (3)» / `error` + «Авария» или «Ждёт утверждения»; сводка — строки «Ожидают утверждения: 4» (тап → C-41), «Остаток абонентки: 3 200 000 сум», «Техдолг: 12 800 000 сум»; плитка «Центр утверждений» — бейдж-счётчик `accent`.
**Наполнение:** баннер приостановки — плашка `error` @ 12%: «Обслуживание приостановлено: не оплачена абонентка. Доступны только аварийные заявки» + кнопка «К оплате» (→ C-44).
**Поведение:** тап по точке → C-35 в разрезе точки; pull-to-refresh; офлайн — кеш + баннер; переходы в C-43/C-44/C-45/C-46/C-47 — из таббара/сводки.

#### C-41. Центр утверждений
**Композиция:** app bar «Утверждения» (бейдж-счётчик) → список карточек, отсортированных по срочности → (пусто «Всё решено»).
**Элементы:** карточка — `surface`: чип типа («Смета» — серый, «Доп-смета» — `warning`, «Вынужденная» — `error` с иконкой `warning`, «Апсейл» — серый, «Пакет дефектов» — `warning`), точка `body`, сумма semibold, возраст «ждёт 3 ч» `caption` (при близкой эскалации — `warning`: «эскалация через 40 мин»); вынужденные и критичные — всегда сверху.
**Наполнение:** пусто — EmptyState `task_alt` «Всё решено»; двойное утверждение — чип-статус «Вы утвердили · ждёт владельца».
**Поведение:** тап → C-36 (или C-42 для пакета); свайп карточки — быстрые «Утвердить»/«Отклонить» для типовых смет с диалогом подтверждения; свыше порога повторной аутентификации свайп-утверждение недоступно — только C-36 с PIN/биометрией; решения офлайн не принимаются (свайпы disabled, карточки из кеша просмотровые).

#### C-42. Пакетное утверждение дефектов (фаза 2)
**Композиция:** app bar «Осмотр: {точка}» → сводка «Найдено 8 дефектов на 5 600 000 сум» → список дефектов с чекбоксами → закреплённая панель «Выбрано 5 · 3 900 000 сум» → primary «Утвердить выбранные» → secondary «Отложить до даты» → destructive «Отклонить».
**Элементы:** строка дефекта — чекбокс + мини-фото + описание + чип приоритета + цена; критичные по умолчанию отмечены и помечены чипом `error` «Критично».
**Наполнение:** диалог отклонения — с полем причины и подписью «Дефекты останутся в архиве с пометкой „отклонено“»; сумма выбранных выше порога — плашка «Потребуется второе утверждение владельцем».
**Поведение:** панель пересчитывается на лету; отправка идемпотентна (частичная ошибка — ретрай без дублей); каждый утверждённый дефект становится заявкой «Утверждена», тост «5 заявок передано диспетчеру»; в MVP экрана нет — push ведёт в C-41, дефекты по одному через C-36.

#### C-43. Техдолг организации (фаза 2)
**Композиция:** app bar «Техдолг» → карточка суммы + тренд → разбивка по точкам (список) → разбивка по приоритетам → primary «Утвердить пакетом».
**Элементы:** тренд — строка `caption`: «Месяц назад: 6 100 000 → сейчас: 4 200 000» со стрелкой `success` вниз (рост — `error` вверх; направление дублируется стрелкой, не только цветом); строка точки — название + сумма + мини-чипы приоритетов; секция «Старше 60 дней» — с подписью `error`.
**Наполнение:** пусто — EmptyState `task_alt` «Техдолга нет»; дефект с истёкшей оценкой — «требует переоценки», в пакет не выбирается.
**Поведение:** тап по точке → C-37 в разрезе точки; «Утвердить пакетом» → C-42.

#### C-44. Финансы организации
**Композиция:** app bar «Финансы» → карточка абонентки с прогнозом → карточка договора → список СФ → динамика по месяцам → primary «Акт сверки за период».
**Элементы:** абонентка — «Остаток: 3 200 000 сум» `h1` + подпись «хватит примерно до 24 августа» + строка «Резерв плановых осмотров: 800 000» `caption`; сверхлимит месяца — строка с суммой; договор — карточка: «Годовой · продление 1 марта 2027», чип `success` @ 12% «Цены зафиксированы по прайсу №14 до продления»; СФ — строки: «Июль 2026 · 5 400 000 сум» + статус-чип («Черновик» — серый, «Отправлена» — `accent`, «Оплачена» — `success`, «Просрочена» — `error`) + иконка `download` (PDF).
**Наполнение:** дунинг — баннеры: T+3 `warning` «СФ не оплачена — 3 дня», T+7 `error` «Оплатите до 10 числа — иначе обслуживание приостановится»; уведомление о смене цен — карточка «При продлении 1 марта изменятся цены» + кнопки «Что изменится» (авто-отчёт) и «Не продлевать» (для месячного договора; диалог-предупреждение о расторжении); пени — отдельной строкой СФ.
**Поведение:** «Акт сверки» — выбор периода (месяцы) → генерация PDF с прогрессом; фильтры по периоду/точке; тап по СФ — просмотр PDF; месячный отчёт-приложение → C-47.

#### C-45. Лимиты и пользователи
**Композиция:** app bar «Лимиты и пользователи» → секция «Точки» (карточки лимитов) → секция «Пользователи» (список) → primary «Пригласить пользователя».
**Элементы:** карточка точки — название + «Лимит на заявку: 500 000» + «Месяц: 640 000 из 1 500 000» (прогресс-бар) + кнопка «Изменить» (bottom-sheet с полями сумм); пользователь — строка: имя, телефон, чип роли («Сотрудник» — серый, «Руководитель точки» — `accent` @ 12%), точка, меню «Деактивировать»; настройка организации — Switch «Показывать сотрудникам сметы и деньги».
**Наполнение:** форма приглашения — поля «Телефон» (+998-маска), «Роль» (радио), «Точка» (выбор); после отправки — тост «Приглашение отправлено SMS»; пороги утверждения — read-only строка с подписью «Задаются договором, меняются через USTAPRO».
**Поведение:** изменение лимита — в пределах договора, валидация с текстом «Максимум по договору: 2 000 000»; каждое изменение — аудит; деактивация — диалог подтверждения.

#### C-46. График осмотров (фаза 2)
**Композиция:** app bar «Осмотры» → ближайшие осмотры (список по точкам) → история осмотров с отчётами.
**Элементы:** строка осмотра — точка, дата «12 августа, 10:00–12:00», периодичность `caption` «раз в квартал», кнопка «Перенести» (запрос переноса — чипы дат недели); история — строки с иконкой `checklist`: «14 мая · найдено 8 дефектов» → отчёт (чек-лист + дефекты) → кнопка «К пакету дефектов» (→ C-42).
**Наполнение:** пусто — EmptyState `event` «Осмотры появятся по графику договора»; приостановка организации — плашка «Осмотры заморожены до оплаты абонентки».
**Поведение:** запрос переноса — уходит диспетчеру, статус «Запрошен перенос»; просмотр отчёта — read-only.

#### C-47. Отчёты организации
**Композиция:** app bar «Отчёты» → переключатель разреза («Организация» / чипы точек) → список месяцев → primary «Скачать PDF» → «Поделиться».
**Элементы:** карточка месяца — сводка: заявки, суммы, списания, сверхлимит; раздел «Техдолг» — «устранено 3 · добавлено 5 · остаток 4 200 000».
**Наполнение:** пусто — EmptyState `description` «Отчёт появится после первого месяца»; язык PDF — из настроек организации (двуязычные шаблоны).
**Поведение:** как C-39: генерация с прогрессом, системный вьювер, share sheet; в реестре заявок PDF — QR на акты.

### 3.8. Режим «Владелец» (C-48)

#### C-48. Дашборд владельца (фаза 2)
**Композиция:** app bar «{Организация}» → карточки «Требуется второе утверждение» (условные) → светофор точек → суммы/техдолг → отчёты — всё read-only.
**Элементы:** карточка второго утверждения — `warning` @ 12%: «Смета 6 400 000 сум · Аптека №12 · руководитель утвердил» + кнопка «Рассмотреть» → C-36 в режиме второго утверждения (PIN/биометрия обязательны); остальные блоки — те же компоненты, что C-40/C-43/C-44/C-47, но без единой операционной кнопки (нет «Утвердить», «Изменить», «Пригласить»).
**Наполнение:** состав блоков настраивается договором; при выключенном двойном утверждении карточек утверждения нет вовсе — чистое наблюдение.
**Поведение:** тапы — только просмотр и скачивание отчётов; pull-to-refresh; офлайн-кеш.

### 3.N. Экраны контура «Дом» (C-51…C-57, M7)

#### C-51. Мой дом
**Композиция:** app bar «{Название объекта}» + переключатель объекта (если их несколько) → **крупная карточка «Аварийная служба»** (высота 80, иконка `emergency`, номер крупно, тап = звонок) → блок «Сейчас в доме» (идущие отключения `ShutdownBanner`) → лента объявлений УК → сетка 2×2 быстрых действий: «Проблема в доме», «Отключения», «Пропуск гостю», «Контакты УК».
**Элементы:** аварийная карточка — единственный элемент с фоном `error` @ 8% и обводкой `error`; объявления — `Card` с датой `caption`; быстрые действия — `radiusChip` с иконкой и подписью.
**Наполнение:** пустое состояние ленты — «В доме сейчас всё спокойно» с иконкой `check_circle`. Плашка `degraded` — `warning`: «Управляющая компания временно не подтверждает доступ. Заявки принимаются в обычном порядке».
**Поведение:** офлайн — весь экран из кеша с меткой «данные на {чч:мм}», кнопки звонка работают всегда.

#### C-52. Сообщить о проблеме в доме
**Композиция:** шаг 1 камера (полноэкранная, как C-09) → шаг 2 плитка категорий 3 колонки → шаг 3 «где» (подъезд/этаж/двор) + необязательный комментарий → отправка.
**Наполнение:** плитка категории — иконка из A-44 + подпись в две строки максимум. Категория с меткой `emergency` подсвечена `error` и при выборе **сразу открывает диалог звонка** в аварийную службу, а не продолжает флоу.
**Поведение:** при дубле по зоне — bottom-sheet «Здесь уже есть обращение от {дата}. Присоединиться?» с двумя кнопками. Не более трёх шагов до отправки.

#### C-53. Отключения и работы в доме
**Композиция:** сегменты «Ближайшие / История» → список `ShutdownBanner` → пустое состояние.
**Наполнение:** карточка — иконка ресурса, «Холодная вода», «Завтра, 09:00–15:00», зона («ваш стояк», «подъезд 3»), причина строкой `caption`. Идущее отключение — обратный отсчёт «осталось ~{N} ч».

#### C-54. Пропуск гостю
**Композиция:** форма (имя, дата, окно, тип, авто — опц.) → primary «Выписать пропуск» → экран результата с **крупным QR** и числовым кодом под ним → кнопка «Поделиться».
**Поведение:** QR минимум 240×240 pt; числовой код — `h1`, моноширинно, с разбивкой по 3 знака.

#### C-56. Согласование доступа в моё помещение
**Композиция:** карточка запроса (кто, зачем, когда, фото и имя мастера + ссылка на верификацию) → три кнопки в столбик: «Подтвердить», «Предложить другое время», «Отказать».
**Наполнение:** заголовок прямым текстом — «Соседу нужен доступ к стояку в вашей квартире», без канцелярита. После подтверждения — карточка с временем и данными мастера, кнопка звонка.

#### C-57. Простой режим
**Композиция:** без app bar и без таббара. Три блока в столбик на весь экран: **«Вызвать мастера»** (высота 80, `accent`), **«Аварийная служба дома»** (высота 80, `error`), **«Мои заявки»** (список, статус словами).
**Элементы:** токены §4.M DEV-06 — `body` 20, цель нажатия 64 pt, контраст ≥ 7:1, отступ между кнопками `s32`.
**Наполнение:** статусы словами: «Заявка принята», «Мастер едет к вам», «Работы идут», «Завершено». Никаких бейджей, точек и процентов.
**Поведение:** телефонные кнопки работают офлайн. Выход из режима — единственный пункт внизу, `body`, без пароля. Режим **не предлагается автоматически по возрасту**.

## 4. Веб-карточка заявки (W-01…W-05)

**Общее:** мобильный веб (mobile-first, SSR/лёгкий SPA ≤ 200КБ), открывается по SMS-ссылке с одноразовым токеном — без установки и регистрации. **Те же токены DEV-06, подключённые как CSS-переменные из `tokens.css`** (DEV-06 §6.2): компоненты `.card`, `.btn`, `.btn--secondary`, `.input`, `.empty-state`, статус-бейджи через тот же маппинг `statusColor`. Шрифт — системный стек. Язык — из профиля клиента (рус/узб), переключатель в шапке. Все действия по ссылке журналируются как подтверждения клиента. Вёрстка одноколоночная, паддинг `--s16`, primary-кнопка — в потоке после контента (не фиксированная: страница короткая).

#### W-01. Статус заявки
**Композиция:** шапка (логотип + переключатель языка) → статус-трекер → карточка мастера → окно/ETA → состав заявки с вилкой → карточка апсейла (условная) → кнопка «Позвонить диспетчеру» (`tel:`) → ссылка на приложение (условная).
**Элементы:** статус-трекер — вертикальный степпер как C-14 (упрощённый: текущий статус-бейдж + пройденные галочки); карточка мастера — `.card`: фото, имя, «★ 4,9 · 312 работ», ссылка «Проверить мастера» → публичная страница верификации; ETA — строка «Мастер в пути, будет ~16:40» (карта не обязательна — текстовый прогноз); апсейл — карточка с плашкой «Это рекомендация — отказ не влияет на текущую работу», фото, позиции, кнопки «Принять» (`.btn`) / «Отклонить» / «Отложить» (`.btn--secondary`) прямо на карточке.
**Наполнение:** приглашение в приложение — один раз после первой закрытой заявки: «В приложении удобнее: история, гарантия, запись в два тапа» + ссылка; никакого повторного баннер-спама.
**Поведение:** автообновление поллингом; решения по апсейлу — на месте, без перехода; токен истёк → W-05; смета ждёт подтверждения → редирект/кнопка на W-02; выполнена → W-03.

#### W-02. Смета — «Согласен»
**Композиция:** шапка → заголовок `h1` «Подтвердите стоимость» → фото → таблица позиций (с ценовыми уровнями запчастей — чипы «эконом/стандарт/премиум») → варианты минимум/полный (для вынужденной) → итог → кнопка «Согласен» (`.btn`) → «Отказываюсь» (`.btn--secondary`) → «Позвонить диспетчеру».
**Наполнение:** тексты и диалог отказа — те же, что C-15/C-16 (единые i18n-строки, словарь общий с приложением); подпись под «Согласен»: «Нажатие фиксируется как ваше подтверждение».
**Поведение:** «Согласен» идемпотентен (повторное нажатие не создаёт второго подтверждения, показывает «Уже подтверждено»); после решения → W-01; токен истёк → W-05.

#### W-03. Акт + оплата
**Композиция:** шапка → «Работа выполнена» → фото до/после (сетка плиток) → работы и материалы → итог → кнопка «Оплатить» → блок чаевых (после оплаты) → «Скачать акт (PDF)» → «Позвонить диспетчеру».
**Элементы:** оплата — кнопки Payme/Click/Uzum-checkout (redirect); чаевые — те же пресеты, что C-20: чипы сумм + своя, «Без чаевых»; гарантия — чип `success` @ 12% «Гарантия до 29 августа».
**Наполнение:** уже оплачено наличными/QR — блок оплаты заменён строкой «Оплачено · наличные мастеру»; ожидание callback — «Проверяем оплату — не закрывайте страницу».
**Поведение:** успех оплаты → чаевые (опционально) → W-04; неуспех — «Оплата не прошла» + повтор/другой способ.

#### W-04. Оценка
**Композиция:** шапка → карточка мастера → 5 звёзд → поле комментария → кнопка «Отправить» → финал «Спасибо!» + одноразовая ссылка на приложение.
**Наполнение:** окно 72 ч истекло — «Спасибо! Окно оценки уже закрыто»; оценка 1–2 — подпись «Расскажите, что случилось — перезвоним и разберёмся».
**Поведение:** звёзды — тап-зоны ≥44px; отправка один раз, повторный заход — «Оценка уже отправлена».

#### W-05. Ссылка недействительна / истекла
**Композиция:** шапка → `.empty-state`: иконка `link_off` → фраза → кнопка «Позвонить диспетчеру» → ссылка на приложение.
**Наполнение:** нейтральный текст без данных заявки: «Ссылка устарела или уже использована. Позвоните диспетчеру — вышлем новую»; ответ одинаков для «нет заявки» и «нет прав» (перебор URL ничего не раскрывает).
**Поведение:** статическая страница, без запросов данных.

## 5. Аналитические события (телеметрия, v2.25)

North Star продукта: **закрытые заявки с оценкой ≥ 4 на активного клиента в месяц**; главная воронка — создание заявки: `order_step_view{step:1}` → `order_submitted` → `estimate_approved` → `payment_succeeded` → `rating_submitted`.

|---|---|---|
| `onboarding_completed` | — | язык выбран, вход завершён (C-01 → C-03) |

## 6. Чек-лист приёмки UI

Прогоняется на каждом экране перед мержем; пункты 1–3 дополнительно ловятся линтом/ревью.

1. **Все строки — из словаря i18n** (`intl_ru.arb`/`intl_uz.arb`): в коде виджетов нет ни одной русской/узбекской строки-литерала; параметры — через ICU (`{sum}`, plural).
2. **Все цвета, радиусы, отступы — токены** `design_tokens.dart`/`tokens.css`: поиск по `Color(0x`, `Colors.`, числовым `EdgeInsets` вне шкалы даёт ноль вхождений (DEV-06 §6).
3. **Статус-бейджи — только через `statusColor(status)`**: цвет статуса нигде не выбирается в компоненте вручную; паузы дают второй бейдж `warning`, «Отменена» — серый с перечёркиванием (DEV-06 §4.3).
4. **Четыре состояния везде:** каждый экран показан в загрузке (скелетоны без шиммера), пустоте (EmptyState: иконка + 1 фраза + 1 действие), ошибке (текст + «Повторить») и офлайне (кеш + баннер «Нет соединения»); юридически значимые действия офлайн — disabled с пояснением.
5. **Тап-зоны ≥ 44×44 pt:** звёзды оценки, чипы, степперы, крестики удаления фото, свайп-кнопки — проверены; в аварийных сценариях кнопки крупнее обычного.
6. **Контраст WCAG AA:** проверены пары «текст статуса на фоне @ 12%», `textSecondary` на `bg`, белый на `accent`; светофор и статусы дублируются иконкой/подписью, а не только цветом.
7. **Узбекская латиница не ломает вёрстку:** прогон экранов с uz-словарём — тексты на 20–30% длиннее русских; кнопки, чипы, бейджи и строки таблиц не обрезаются многоточием на ключевых словах, переносы допустимы; спецглифы oʻ/gʻ рендерятся системным шрифтом.
8. **Динамический шрифт ОС:** экран не разваливается на масштабе текста до 130%; критичные суммы и кнопки остаются видимыми без скролла-ловушек.
9. **Тестовые размеры экранов:** прогон на малом Android (~360×640, бюджетные устройства Ташкента), стандартном (~390×844) и планшетном/крупном (≥600 dp ширины — контент не растягивается на всю ширину, ограничен читаемой колонкой); веб-карточка — 320px ширины минимум.
10. **Одна primary-кнопка на экран, деньги и даты по форматам §1** («1 250 000 сум» с пробелами, «сегодня 16:00», «~16:40»); TalkBack/VoiceOver-метки заданы для всех кнопок действий, особенно «Согласен»/«Отказываюсь»/«Утвердить».
