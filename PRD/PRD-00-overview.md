## Правила чтения пакета
1. **Конфликт между PRD и ТЗ трактуется в пользу ТЗ v2.25** — сообщите о конфликте, это дефект пакета.
2. Идентификаторы: экраны C-xx (клиент), W-xx (веб-карточка), M-xx (мастер), D-xx (диспетчерская), A-xx (админка), L-xx (лендинги); функции F-xx внутри каждого PRD; сервисы — нумерованные разделы PRD-05.
3. Каждый экран описан блоками: Назначение / Кто видит / Точки входа / Данные / Элементы и действия / Состояния (загрузка, пусто, ошибка, офлайн) / Переходы / Крайние случаи / Ссылки на ТЗ.
4. Фазы: MVP / Фаза 2 / Фаза 3 — проставлены у каждой функции. Оценивать в первую очередь MVP-контур.
5. Все конфигурируемые значения собраны в сводной таблице параметров (PRD-04, 123 позиции) — в коде не должно быть «магических чисел».

## Ключевые продуктовые принципы (нарушать нельзя — из ТЗ, раздел 1)
1. Заявка — центральная сущность; все деньги и отчёты — производные её жизненного цикла.
2. Фотофиксация — условие перехода статуса (проверка на API, не только в UI).
3. Ни одна платная работа без санкции клиента; исключения — аварийная локализация и консервация.
4. Отчёт — побочный продукт правильно закрытой заявки.
5. Доля мастера — от базового B2C-прайса с наценками; скидки клиенту долю не трогают.

## Глоссарий (минимум для чтения)
- **Точка** — объект B2B-организации (аптека, ресторан); носитель лимитов и техдолга.
- **Лента** — план дня мастера: упорядоченные заявки со слотами (30 мин) и дорожными буферами.
- **Якорная / гибкая заявка** — жёсткое окно клиента vs двигаемая (осмотр, лист ожидания).
- **Срочно / лист ожидания** — платный приоритет (+30% к работам) vs бесплатное ожидание свободной ёмкости.
- **Доп-смета вынужденная / апсейл** — «без этого не завершить» vs «рекомендую заодно»; разные правила (ТЗ 4.6).
- **Этапная работа** — сессии с технологическими паузами (стяжка, малярка); инвариант: этап 1 не стартует без слотов остальных.
- **Парная работа** — ведущий + помощник, деньги по ролям.
- **Дежурный** — мастер дня без плановых броней (аварии, замены), с гарантированной минималкой смены.
- **Консервация** — безопасное отключение при отказе клиента от вынужденных работ.
- **Техдолг** — реестр дефектов точки; источники: осмотры, отклонённые вынужденные работы, отложенные апсейлы.
- **Сумка** — расходники мастера, списываемые по фикс-прайсу без чеков.
- **Код закупки** — одноразовый код заявки для партнёрского магазина (закупка в долг компании).
- **Паспорт техники (ClientAsset)** — учёт техники клиента для постпродажных касаний.
- **QC-прозвон** — контроль качества звонком по выборке закрытых заявок (матрица ТЗ 17.11).
- **Дунинг** — этапы взыскания дебиторки (T+3/7/10/30/60).
- **Абонентка** — авансовый счёт B2B-организации; выручка признаётся по факту работ.
- **Релиз прайса (PriceListRelease)** — снапшот позиций и коэффициентов; заявка/договор фиксируют релиз, изменения цен не пересчитывают действующее (ТЗ 3.7).
- **Программа баллов / ваучеры** — % от суммы работ заявителю точки → ваучеры супермаркета из пула; только как опция договора с согласия организации (ТЗ 17.14).
- **Лицензиат** — партнёр-субподрядчик для лицензируемых работ (газ, лифты), агентская комиссия (ТЗ 17.8).
- **Годовой / месячный договор** — годовой: цены заморожены весь срок; месячный: перевод на текущий релиз при каждом продлении (ТЗ 18-п.17).

## Открытые зависимости перед стартом разработки (вне кода)
Юрист: потолок ответственности (ТЗ 17.7), формулировки оферты, локализация персданных (ЗРУ-547), формулировки пункта договора о программе мотивации персонала (17.14). Бухгалтер: налоговый контур (ТЗ 8.10), фискализация ОФД, формат 1С, НДФЛ и оформление ваучеров-подарков физлицам (17.14). Бизнес: договор с лицензиатом (газ/лифты), размер реферального бонуса, стартовые партнёрские магазины, условия закупки ваучеров у Корзинки.
