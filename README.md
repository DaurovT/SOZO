# SOZO (USTAPRO) — платформа технического сервиса

Ташкент. Клиент вызывает мастера, мастер выполняет работу, диспетчер и админ
управляют потоком. Три контура: **B2C** (частные клиенты), **B2B** (сети —
аптеки, офисы, магазины) с лимитами, утверждениями сметы и актами осмотра, и
**«Дом»** (ТЗ §19) — управляющие компании и службы эксплуатации как клиенты
подписки, наряды-допуски в общие зоны, портал жителя.

> **Новой сессии Claude или новому разработчику:** начните с
> **[docs/HANDOVER.md](docs/HANDOVER.md)** — там состояние, ловушки и
> договорённости. Этот файл про то, как запустить и выложить.

## Быстрый старт

Нужны **Node 22 LTS** и **Flutter 3.44+**. Базы данных не нужны.

```bash
cd sozo
npm install && npm run build     # contracts → kernel → api
npm run api                      # http://localhost:3000/v1
```

Веб-панели:

```bash
npm run admin                                  # http://localhost:5173
cd apps/dispatcher-web && npm run dev          # http://localhost:5174
npm run operator                               # http://localhost:5176/operator/
```

Мобильные приложения — адрес сервера задаётся при сборке:

```bash
cd apps/client-app
flutter run --dart-define=SOZO_API=http://<IP-компьютера>:3000
```

На телефоне `localhost` не работает: нужен адрес компьютера в той же сети.
Если адрес сменился, а приложение уже установлено — менять его можно прямо в нём:
на экране ошибки есть **«Изменить адрес сервера»**.

### Вход

Код подтверждения в dev-режиме — **`00000`** для любого номера.
Демо-аккаунты перечислены в [docs/HANDOVER.md](docs/HANDOVER.md#4-демо-аккаунты);
главный — `+998900000000` (админ + все роли B2B + заявки B2C).

## Данные

Состояние целиком лежит в **одном файле**: `sozo/apps/api/data/state.json`
(~5 МБ). Путь переопределяется переменной `STATE_FILE`.

**Этого файла нет в репозитории** — каталог `data/` закрыт в `sozo/.gitignore`
намеренно, как dev-хранилище. Из этого следует:

- **Репозиторий не является бэкапом данных.** Единственная копия живёт на той
  машине, где сервер работал. Бэкап — отдельная задача: копия этого файла по cron.
- На свежем клоне поднимутся только константы из конструкторов сервисов: админ,
  бухгалтер, диспетчер, две демо-организации, релиз прайса №1. Заявок,
  адресов и истории не будет.
- Полная демо-картина — через `POST /v1/app/demo/seed` под диспетчером
  (`+998900000002`, код `00000`). Повторный вызов копий не плодит.

Postgres, Redis и MinIO в `sozo/infra/docker-compose.yml` — заготовка на
будущее, **в рантайме не используются**.

## Проверки

```bash
# Ядро — юнит-тесты (сервер не нужен)
cd sozo && npm test              # 57 тестов: деньги, графы заявок и нарядов-допусков

# База — миграции и инварианты на настоящем PostgreSQL без установки сервера
cd sozo && npm run db:check      # 13 проверок на PGlite (WASM): RLS, CHECK-и

# API — сквозные прогоны. Сервер поднимать не нужно: раннер стартует его сам
cd sozo/apps/api
npm run test:e2e                 # все шесть наборов, 342 проверки
npm run test:e2e -- home-contour # один набор

# Flutter
cd sozo/apps/client-app && flutter analyze && flutter test    # 97 тестов
cd sozo/apps/master-app && flutter analyze && flutter test    # 75 тестов
```

**Про e2e и данные.** Раньше прогоны опирались на dev-состояние
(`sozo/apps/api/data/state.json`), которого нет в репозитории — оно закрыто в
`.gitignore` намеренно. Это давало два тихих провала: `b2b-access-e2e` на свежем
клоне выдавал 9 из 24, а любой набор, запущенный вторым разом подряд, валился
на накопленных данных (подписка начислена дважды, наряды остались с прошлого
раза). Оба закрыты: `test/run-e2e.mjs` поднимает API на одноразовом состоянии во
временной папке, а `b2b-access-e2e` заводит свои фикстуры сам. Прогон повторяем.

Запускать наборы вручную против рабочего сервера по-прежнему можно
(`node test/home-contour-e2e.mjs [url]`), но состояние он засорит.

Тесты клиента проверяют не только «экран построился», но и что он **виден и
помещается** на 390×844 — переполнение по ширине иначе всплывает только на
телефоне.

## Языки

Три: русский (основа), узбекский, английский. Переключаются мгновенно, без
перезапуска.

Половина текста приходит с сервера — названия категорий, статусы, уведомления.
Поэтому приложение обязано слать заголовок `Accept-Language`, а сервер держит
свои словари: `locale-uz.ts` и `locale-en.ts`. Ключ там — сама русская строка.

Подробности и правило «что нельзя класть в общий словарь» —
в [docs/HANDOVER.md](docs/HANDOVER.md#7-языки).

## Выкладка на сервер

### Перенос на VPS: что взять с собой

**`git clone` переносит код, но не данные.** Состояние живёт в одном файле
`sozo/apps/api/data/state.json`, а каталог `data/` закрыт в `.gitignore`
намеренно. На свежем клоне поднимутся только константы из конструкторов
сервисов: админ, бухгалтер, диспетчер, две демо-организации, релиз прайса №1 —
ни заявок, ни адресов, ни истории.

Поэтому файл копируется отдельно, руками, до первого запуска на сервере:

```bash
# с машины разработки
scp sozo/apps/api/data/state.json user@vps:/var/lib/sozo/state.json
```

и сервер запускается с `STATE_FILE=/var/lib/sozo/state.json`. Путь вне каталога
приложения выбран сознательно: `git pull` и пересборка тогда не могут задеть
данные.

Если данные не нужны — не копируйте, но знайте, что демо-картина собирается
`POST /v1/app/demo/seed` под диспетчером (`+998900000002`, код `00000`), а
заявки и история не восстановятся ниоткуда.

**Что ещё не переносится через git:** `node_modules` (ставится `npm ci`),
сборки `dist/` и `build/`, и сами Flutter-артефакты — их пересобирают на месте
с боевым адресом (см. пункт 9 ниже).

**Docker на VPS есть — и это снимает главный блокер проекта.** Заготовка
`sozo/infra/docker-compose.yml` (Postgres, Redis, MinIO) до сих пор не
использовалась в рантайме только потому, что на машине разработки Docker не
поднят. Схема на 37 моделей, миграции RLS и инвариантов написаны и проверены
на PGlite — переход на настоящий Postgres перестаёт быть теоретическим.

### Порты

Открыть в файрволе ровно три:

| Порт | Откуда | Зачем |
|---|---|---|
| 443/TCP | отовсюду | Единственный публичный порт приложения |
| 80/TCP | отовсюду | Выпуск сертификата Let's Encrypt и редирект на HTTPS |
| 22/TCP | **только свой IP** | SSH |

**Не открывать:** `3000` (API стоит за nginx на `127.0.0.1`), `5432`, `6379`,
`9000`, `9001` (не используются, а появятся — только на localhost), `5173`–`5176`
(это dev-серверы Vite: админка, диспетчерская, лендинг, кабинет оператора —
в проде их нет).

Вебхуки Payme и Click придут на 443 — отдельного порта не нужно, но нужен
публичный домен с валидным сертификатом.

### Порядок

1. DNS заранее: `api.`, `admin.`, `dispatch.`, корень — все на один IP.
   Записи должны разойтись до выпуска сертификата.
2. Ubuntu 24.04 LTS, минимум 2 vCPU / 4 ГБ. На 1 ГБ сборка падает по памяти
   (`tsc` + `vite build`); либо больше памяти, либо собирать локально и
   отгружать готовый `dist`.
3. **Статический IP.** С динамическим адрес слетает при перезапуске машины, и
   мобильные сборки перестают достукиваться.
4. Node 22 LTS, nginx, certbot. Swap 2 ГБ, `ufw`, `unattended-upgrades`.
5. `npm ci && npm run build` в `sozo/`.
6. systemd-юнит для API: `PORT=3000`, `STATE_FILE=/var/lib/sozo/state.json`,
   `NODE_ENV=production`, `JWT_SECRET=<длинная случайная строка>`,
   `Restart=always`.
7. nginx: `api.домен` → `127.0.0.1:3000`; `admin.` и `dispatch.` — статика из
   `dist`. Затем certbot на все поддомены.
8. **Cron-бэкап `state.json`.**
9. Пересобрать приложения на боевой адрес:
   `--dart-define=SOZO_API=https://api.домен`,
   веб — `VITE_API_URL=https://api.домен/v1`.

### Обязательно до публичного адреса

Три вещи, без которых выкладывать нельзя:

1. **Код `00000` работает всегда** — проверки на окружение нет. Кто знает номер,
   войдёт под этим человеком, включая администратора.
2. **`JWT_SECRET` по умолчанию `dev-only-change-me`** — токен с любой ролью
   подпишет кто угодно, кто видел репозиторий.
3. **CORS `origin: true`** — отражает любой источник, надо сузить до своих
   доменов.

Подробно — [docs/HANDOVER.md](docs/HANDOVER.md#3-три-блокера-до-публичного-адреса).

### Про размещение

У Azure нет региона в Узбекистане; ближайший по задержке — UAE North (Дубай),
~40–60 мс до Ташкента, европейские дают 80–120 мс. При этом в `DEV-04` записано
«прод — два сервера в ЦОД РУз», а в Узбекистане действует требование о
локализации персональных данных граждан. Для демо и пилота вопросов не возникнет,
но перед боевыми данными это стоит сверить с юристом — переезжать с живой базой
дороже.

## Контур «Дом»: что сделано и что осталось

Управляющие компании и службы эксплуатации как клиенты подписки. Концепция —
**ТЗ §19**, детальная спецификация — **DEV-15**, экраны кабинета — **PRD-07**,
граф наряда-допуска — **DEV-10 §7**, трекер переделки — **DEV-16**.

### Две модели монетизации (не путать)

| | **Подписка** — БЦ, свои техотделы, FM | **Доступ** — ЖК с УК |
|---|---|---|
| Платит | 3 000 000 сум за объект в месяц | ничего |
| Свои мастера в системе | да | нет |
| Заявка мастеру платформы | достаётся платформе целиком | платформа делит с мастером, **5% уходит УК** |
| Сервисный сбор оператору | нет | 5% с частных заявок жителей |

Модели взаимоисключающи: подписчик сбора не получает. Правило живёт в одной
точке — `BuildingsService.effectiveServiceFeeBps()`.

### Сделано

**Спецификации.** ТЗ доведено до v2.26 (раздел 19), новые DEV-15…DEV-18 и PRD-07,
обновлены все существующие PRD и DEV: экраны, параметры 124–139, таймеры 55–64.

**Бэкенд — полностью.** Пять модулей (`buildings`, `access`, `subscriptions`,
`sla`, `operator-api`, ~2 900 строк) плюс интеграции в `orders` и `billing`:

- наряд-допуск с графом DEV-10 §7 и гейтами: заявку нельзя начать без открытого
  наряда, закрыть — с невключённым ресурсом;
- запрет лицензируемых зон мастерам платформы (ТЗ 17.8) и авто-согласие
  молчанием с абсолютным исключением для критичных зон;
- отключения ресурсов с зоной влияния по стоякам и запретом двух бригад на одном;
- замечания и обходы с дедупликацией и закрытием только по фото устранения;
- право первой руки, сервисный сбор, нетто-расчёт с оператором;
- развилка жителя: «в моей квартире» / «в доме» и выбор исполнителя.

**База.** Схема (37 моделей), миграции RLS и инвариантов. Проверяются
командой `npm run db:check` на настоящем PostgreSQL в WASM — сервер не нужен.

**Тесты.** 57 юнит-тестов ядра, **392 e2e** в шести наборах, 13 проверок БД,
**97 + 75** тестов мобильных. Прогон повторяем: раннер поднимает API на
одноразовом состоянии.

Три проверки стерегут ошибки, которые не видит ни анализатор, ни дымовой
прогон, потому что экран при них строится и падает только на действии:

- **ключи словаря** — незнакомый ключ `t()` возвращает как есть, и на экране
  появляется `walk.zavershitObhod` вместо текста, а прогон зелёный: кириллицы
  в такой строке нет;
- **иконки справочника A-44** обязаны существовать в `assets/icons` — иначе
  плитка быстрой фиксации пустая ровно там, где счёт идёт на секунды;
- **именованные маршруты** запрещены, пока в `MaterialApp` нет `routes` или
  `onGenerateRoute`: `pushNamed` на несуществующий маршрут роняет приложение.

**Кабинет оператора** собран по порядку DEV-15 §14: дашборд, наряды, первая рука, настройки объекта, помещения и жители, отключения, замечания и обходы, журнал доступа, финансы. Заглушек не осталось; D-21 в
диспетчерской; макеты восьми экранов в `design-home/`.

**A-39 — модерация подключений.** Заявка на объект не даёт прав: она встаёт
в очередь, и выше `claimed` объект поднимается только решением человека. Два
заявителя на один дом **замораживают друг друга** — платформа не арбитр в споре
хозяйствующих субъектов. Главный сигнал верификации работает на данных, которые
старше заявки: контакт ТСЖ/УК из паспортов точек A-09, внесённый мастерами при
первых осмотрах, — подделать его задним числом нельзя.

**Приложение мастера: M-43…M-45.** Наряд-допуск, пропуск с QR и резервным кодом,
отметки отключения ресурса. Офлайн-контракт соблюдён: наряд приезжает в устройство
вместе с заявкой, действия уходят в очередь, а гейт старта решается по кешу —
если наряд не согласован, экран называет причину словами, а не гасит кнопку молча.

**W-06 — согласование по SMS-ссылке.** Страница `/p/{код}` отдаётся сервером,
без JS и без регистрации: консьерж открывает ссылку из SMS и решает в один тап.
Короткие отзываемые коды вместо JWT — SMS кириллицей вмещает 70 символов.
Это снимает главный блокер Free-тарифа: требовать освоения кабинета ради двух
нажатий в день бессмысленно, а на согласованиях этого человека держится весь
контур доступа.

**Админка — A-39…A-43.** Очередь модерации с сигналами сверки и баннером
конкурирующей заявки, реестр операторов с долей просрочки за 30 дней, справочник
зон с разделением критичных и лицензируемых, биллинг подписок с разбором
взаимозачёта — на экране видно, какая из двух моделей применена к объекту.

**Лендинг — L-09, L-10.** Страница для эксплуатирующих организаций: четыре
сегмента, калькулятор **дохода** (единственный в пакете — остальные считают
расход) и форма подключения. Публичная карточка дома по QR с наклейки в
подъезде: первым экраном кнопка звонка, аварийный телефон, ближайшие отключения,
а для неподключённого дома — сбор спроса. Неподключённый и несуществующий объект
отвечают одинаково: иначе перебором кодов составляется реестр наших домов.

**A-44 — категории замечаний.** Категория перестала быть свободной строкой:
серьёзность и предлагаемый маршрут подставляются из справочника, указанные на
месте важнее умолчаний. Аварийная категория создаёт заявку сама — всегда как
общее имущество, то есть только службе оператора.

**Справочник зон сведён к одному источнику.** Знание о зонах жило в четырёх
местах, и подписи уже разъехались: в SMS консьерж читал «вентиляционная
камера», инженер в кабинете видел «камера дымоудаления». Полноту покрытия
стережёт компилятор.

**Мастер: M-48…M-50.** Режим «Обход» — маршрут с чек-листом, фиксация
замечания в три тапа, «Мои замечания». Офлайн-первый целиком: дедупликация
работает в подвале, потому что открытые замечания приезжают вместе с
маршрутом, а не запрашиваются в момент съёмки.

**Мастер: M-14 «наряд есть, не пускают».** Единственная причина отказа в
доступе, которая не ставит паузу. Пауза означает «ждём, пока договорятся», но
договариваться поздно: согласование получено, окно допуска идёт, а второй раз
согласовывать — ещё сутки. Вместо паузы эскалация дежурному объекта с
таймером, заявка остаётся за мастером.

**Справочники сведены к одному источнику.** Подписи зон жили в пяти местах,
подписи ресурсов — в четырёх, и они уже разъехались: мастер видел
«Вентиляционная камера», а консьерж в SMS по тому же наряду — «Камера
дымоудаления»; жителю приходило «Отопление», мастеру в наряде — «отопление».
Полноту покрытия зон стережёт компилятор: уберите зону из справочника, и
сборка упадёт с её именем. Браузерные приложения справочники не импортируют,
а получают по сети — пакет контрактов собирается в CommonJS под API, а Vite
не трансформирует CJS вне `node_modules`.

**Прогоны e2e больше не зависят от машины разработчика.** Раньше второй запуск
подряд валился на накопленных данных (подписка начислена дважды, наряды
остались с прошлого раза), а `b2b-access` на свежем клоне давал 9 из 24.
Теперь `npm run test:e2e` поднимает API на одноразовом состоянии во временной
папке, а фикстуры набор заводит сам.

### Осталось

| Этап | Объём | Примечание |
|---|---|---|
| **PostgreSQL вместо памяти** | 3–4 нед | Стори M0-E2-S1. **На VPS блокер снят** — Docker там есть. Делать блоком: половина модулей на Prisma и половина в памяти — худшее состояние |
| **Клиент: C-52, C-53, C-54, C-56** | 2–3 нед | Сообщить о проблеме в доме, календарь отключений, пропуск гостю, согласование доступа в помещение. C-51 «Мой дом» и C-57 «Простой режим» уже есть |
| **Мастер: M-46, M-47** | ~1 нед | Своя выработка в смене оператора, плановое ТО на объекте |
| **Юристы — 4 пункта** | параллельно | DEV-17. Блокируют первую продажу, не разработку |

**Порядок на VPS.** Сначала три блокера безопасности (ниже) — без них публичный
адрес открывать нельзя. Потом PostgreSQL, раз Docker наконец доступен: это
единственный этап, который дальше только дорожает. Клиентские экраны и M-46/M-47
можно вести параллельно — они не зависят от базы.

### Известные расхождения

- `sozo/apps/api` работает на in-memory (`state.json`), Prisma не подключена —
  RLS-политики применить некуда, инварианты продублированы кодом.
- На экране C-51 «Мой дом» **убрана карточка «Что можно»**. Она вела на
  маршруты `/building/report`, `/building/shutdowns` и `/building/pass`,
  которых не существует, и нажатие роняло приложение: во всём остальном
  приложении экраны открываются через `MaterialPageRoute`, таблицы маршрутов
  в `MaterialApp` нет вовсе. Кнопка, которая падает, хуже отсутствующей, а
  заглушку «скоро» этот продукт не ставит. Ближайшие отключения житель и так
  видит выше на том же экране; карточка вернётся вместе с C-52…C-54 и их
  эндпоинтами (`POST` замечания от жителя и выпуск гостевого пропуска — их на
  сервере пока нет).
- Макетов новых экранов нет ни для одного приложения, кроме восьми в
  `design-home/`; дизайн обязан опережать разработку на спринт.
- Один web-разработчик на четыре панели: кабинет — критический путь.

## Договорённости по работе

- **Git используется** (репозиторий на GitHub, ветка `main`). Docker на машине
  разработки не поднят — поэтому база проверяется на PGlite (`npm run db:check`),
  а приложение до сих пор работает на in-memory. **На VPS это перестаёт быть
  ограничением** — см. «Перенос на VPS».
- Деньги везде в **тийинах** (целые числа), не в суммах.
- Комментарии и интерфейс — по-русски.
- Дизайн сверяется с Figma по номеру узла, «1в1» означает буквально.
- Цвета и отступы — только через `design_tokens.dart`, в экранах ни одного hex.
