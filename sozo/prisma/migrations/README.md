## Проверка без установки сервера БД

```bash
npm run db:check
```

Прогоняет миграции на **настоящем PostgreSQL 18** (PGlite, WASM — ставится как npm-пакет, сервер в системе не нужен) и проверяет, что инварианты держит именно база, а не только код:

- ставка сервисного сбора выше 10% отклоняется;
- объект не переводится в `active` без аварийного телефона;
- сервисный сбор на общем имуществе отклоняется;
- **RLS реально изолирует**: оператор видит свой объект, чужой оператор — ничего, роль платформы — видит.

Инвариант п.9 в PGlite пропускается: там нет `btree_gist`. В проде он применяется отдельной миграцией, до неё правило держится проверкой в `AccessService.createShutdown`.

## Важное про RLS

`SET LOCAL` действует **только внутри транзакции** — это не рекомендация, а проверенный факт: без транзакции политики не видят контекст и запрос возвращает пусто. Отсюда требование DEV-07 §8 п.4: пулер обязан работать в transaction mode.
